Хорошо, вот набор из 4 практических работ по настройке загрузчика GRUB в Debian, уровня junior.

**Практическая работа №1: Базовая настройка меню загрузки**

**Задание:**
1.  Отредактируйте основной файл конфигурации GRUB.
2.  Измените таймаут (время ожидания выбора) на 10 секунд.
3.  Измените пункт загрузки по умолчанию (например, на второй в списке).
4.  Отключите графический терминал, чтобы меню отображалось в текстовом режиме.
5.  Примените изменения, обновив конфигурацию GRUB.
6.  Перезагрузитесь и проверьте результат.

**Решение и пояснения:**
```bash
sudo nano /etc/default/grub          # 1. Редактирование конфига
# Измените или добавьте строки:
GRUB_TIMEOUT=10                      # 2. Пауза в 10 секунд
GRUB_DEFAULT=1                       # 3. Второй пункт (нумерация с 0)
GRUB_TERMINAL=console                 # 4. Текстовый режим вместо графического
sudo update-grub                      # 5. Применение изменений, пересборка /boot/grub/grub.cfg
sudo reboot                           # 6. Перезагрузка для проверки
```
**Пояснения:** Основной файл конфигурации — `/etc/default/grub` . Прямое редактирование `/boot/grub/grub.cfg` не рекомендуется, так как его изменения будут перезаписаны. Для вступления в силу правок всегда нужно запускать `update-grub` . `GRUB_DEFAULT=1` выберет второй пункт меню (где первый имеет индекс 0) .

**Практическая работа №2: Передача параметров ядру**

**Задание:**
1.  Настройте GRUB для передачи ядру параметра, отключающего тихий режим загрузки (verbose).
2.  Добавьте параметр, который принудительно устанавливает разрешение экрана для GRUB.
3.  Проверьте текущие параметры ядра, с которыми загрузилась система.
4.  Удалите параметр "quiet" и добавьте параметр "verbose".
5.  Обновите конфигурацию и перезагрузитесь.
6.  Временно добавьте параметр `single` для загрузки в однопользовательском режиме прямо из меню GRUB.

**Решение и пояснения:**
```bash
sudo nano /etc/default/grub
# Найдите строку GRUB_CMDLINE_LINUX_DEFAULT и измените:
GRUB_CMDLINE_LINUX_DEFAULT="verbose"  # 2,4. Заменяем quiet на verbose
GRUB_GFXMODE=1024x768                  # 3. Устанавливаем разрешение для графического меню
sudo update-grub
sudo reboot
# После перезагрузки проверьте параметры ядра:
cat /proc/cmdline                     # 3. Проверка текущих параметров
# 6. Временное изменение (для разового входа):
# В меню GRUB выбрать нужную запись, нажать 'e', найти строку, начинающуюся с linux,
# дописать в её конец 'single' и нажать Ctrl+X для загрузки.
```
**Пояснения:** Параметры ядра задаются в переменных `GRUB_CMDLINE_LINUX` и `GRUB_CMDLINE_LINUX_DEFAULT` . `quiet` скрывает вывод загрузочных сообщений, `verbose` — показывает. Параметр `single` позволяет загрузиться в однопользовательском режиме для восстановления . Временное редактирование в меню (по клавише 'e') действует только для текущей загрузки.

**Практическая работа №3: Добавление собственного пункта меню**

**Задание:**
1.  Создайте пользовательский скрипт для добавления новой записи в меню GRUB.
2.  Добавьте запись для загрузки другой ОС (например, тестового ядра или FreeBSD) с помощью ручной конфигурации.
3.  В записи укажите, что корневая файловая система находится на втором разделе первого диска.
4.  Обновите конфигурацию GRUB.
5.  Проверьте наличие новой записи в меню при загрузке.
6.  Удалите созданный скрипт и снова обновите конфигурацию.

**Решение и пояснения:**
```bash
# 1. Создаем исполняемый скрипт в директории /etc/grub.d/
sudo nano /etc/grub.d/40_custom
# Добавьте содержимое:
#!/bin/sh
exec tail -n +3 $0
# Добавьте свою запись:
menuentry 'Моя тестовая система' {
        set root='hd0,gpt2'          # 3. Указываем раздел (hd0,msdos2 для MBR)
        chainloader +1               # Для Windows или другого загрузчика
}
# 2. Для загрузки конкретного ядра Linux (пример):
# menuentry 'Старое ядро' {
#         set root='hd0,msdos1'
#         linux /vmlinuz-4.19.0 root=/dev/sda2 ro
#         initrd /initrd.img-4.19.0
# }

sudo chmod +x /etc/grub.d/40_custom   # Делаем скрипт исполняемым
sudo update-grub                       # 4. Пересборка конфига
# 5. При следующей загрузке новая запись появится в меню.
# 6. Удаление:
sudo rm /etc/grub.d/40_custom
sudo update-grub
```
**Пояснения:** Все скрипты в `/etc/grub.d/` выполняются по порядку для генерации финального `/boot/grub/grub.cfg` . Файл `40_custom` предназначен для пользовательских правок и не перезаписывается при обновлениях. Команда `chainloader +1` передает управление другому загрузчику на указанном разделе.

**Практическая работа №4: Восстановление GRUB**

**Задание:**
1.  Сымитируйте ситуацию (или используйте виртуальную машину), где GRUB не загружается.
2.  Загрузитесь с LiveCD/USB Debian.
3.  Определите, где находится корневой раздел вашей основной системы.
4.  Смонтируйте корневой раздел в `/mnt`.
5.  Переустановите GRUB в MBR (Master Boot Record) диска.
6.  Обновите конфигурацию GRUB из "chroot" среды и перезагрузитесь.

**Решение и пояснения:**
```bash
# 2. Загружаемся с Live-носителя и открываем терминал.
sudo fdisk -l                         # 3. Определяем разделы (например, /dev/sda1 - корень, /dev/sda - диск)
sudo mount /dev/sda1 /mnt              # 4. Монтируем корень
# Если есть отдельный загрузочный раздел (/boot), монтируем и его:
# sudo mount /dev/sda2 /mnt/boot

# 5. Переустановка GRUB:
sudo grub-install --root-directory=/mnt /dev/sda   # Устанавливаем GRUB на диск /dev/sda
# Или, если нужна смена окружения:
# sudo mount --bind /dev /mnt/dev
# sudo mount --bind /proc /mnt/proc
# sudo mount --bind /sys /mnt/sys
# sudo chroot /mnt /bin/bash
# grub-install /dev/sda
# update-grub
# exit

# 6. Если использовался прямой метод с --root-directory, то конфигурацию обновлять не нужно.
# Если использовался chroot, то update-grub выполняется внутри него.
sudo reboot
```
**Пояснения:** При повреждении загрузчика проще всего восстановить его из live-системы . Параметр `--root-directory` указывает `grub-install`, где находится корень устанавливаемой системы . Команда устанавливает загрузчик в MBR диска (`/dev/sda`), а не в раздел (`/dev/sda1`).
