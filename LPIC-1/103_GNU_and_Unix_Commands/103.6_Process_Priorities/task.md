**Практическая работа №1: Приоритеты процессов**

**Задание:**
1. Определите значение nice по умолчанию для нового процесса.
2. Запустите `sleep` с пониженным приоритетом (nice 10).
3. Запустите `sleep` с повышенным приоритетом (nice -5).
4. Посмотрите значения nice запущенных процессов.
5. Объясните диапазон значений nice.

**Решение и пояснения:**
```bash
nice                              # 1. Значение по умолчанию (обычно 0)
nice -n 10 sleep 300 &            # 2. Пониженный приоритет
sudo nice -n -5 sleep 300 &       # 3. Повышенный (нужен root)
ps -o pid,ni,cmd -C sleep         # 4. Колонка NI
```
**Пояснения:**
Nice-значение от -20 (наивысший приоритет) до +19 (наинизший). Обычный пользователь может только понижать приоритет (увеличивать nice). Повышение приоритета (отрицательный nice) требует прав root.

**Практическая работа №2: Изменение приоритета работающего процесса**

**Задание:**
1. Запустите процесс в фоне.
2. Найдите его PID.
3. Измените его nice на 15.
4. Проверьте новое значение.
5. Верните приоритет к обычному (с правами root).

**Решение и пояснения:**
```bash
sleep 600 &
PID=$!                            # 2. PID последнего фонового процесса
renice 15 -p $PID                 # 3. Понижение приоритета
ps -o pid,ni,cmd -p $PID          # 4. Проверка
sudo renice 0 -p $PID             # 5. Возврат к 0
```
**Пояснения:**
`renice` меняет приоритет уже запущенного процесса. Понижение приоритета (увеличение nice) доступно владельцу процесса, повышение — только root. Фоновая задача `$!` хранит PID последнего запущенного в фоне процесса.

**Практическая работа №3: Мониторинг приоритетов в top**

**Задание:**
1. Запустите `top` и отсортируйте процессы по nice.
2. Измените nice процесса прямо из `top`.
3. Понизьте приоритет процесса через `top` (клавиша `r`).
4. Найдите процессы с отрицательным nice.
5. Объясните, как nice влияет на планирование.

**Решение и пояснения:**
```bash
top                               # 1. Внутри: нажмите 'r' для renice
# В top: 'r' -> введите PID -> введите новое значение nice
ps -eo pid,ni,cmd --sort=ni | head        # 4. Процессы с низким nice
```
**Пояснения:**
В `top` клавиша `r` позволяет изменить nice процесса без выхода. Планировщик CFS распределяет процессорное время с учётом nice: чем выше nice, тем меньшую долю CPU получает процесс при конкуренции.

**Практическая работа №4: Приоритеты ввода-вывода (ionice)**

**Задание:**
1. Проверьте, установлена ли утилита `ionice`.
2. Запустите команду с классом ввода-вывода idle.
3. Запустите команду с высоким приоритетом I/O.
4. Посмотрите текущий класс I/O процесса.
5. Объясните разницу между nice и ionice.

**Решение и пояснения:**
```bash
ionice                            # 1. Проверка (пакет util-linux)
ionice -c 3 dd if=/dev/zero of=/tmp/test bs=1M count=100   # 2. Idle-класс
sudo ionice -c 1 -n 0 dd if=/dev/zero of=/tmp/test bs=1M count=100  # 3. Realtime
ionice -p $$                      # 4. Класс I/O текущей оболочки
```
**Пояснения:**
`ionice` управляет приоритетом дискового ввода-вывода: класс 1 — realtime, 2 — best-effort (с уровнем 0-7), 3 — idle (только когда диск свободен). `nice` влияет на CPU, `ionice` — на дисковые операции.
