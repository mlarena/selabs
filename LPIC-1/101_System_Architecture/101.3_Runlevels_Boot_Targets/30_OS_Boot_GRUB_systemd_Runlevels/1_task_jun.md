**Практическая работа №1: Работа с уровнями выполнения (runlevels/targets)**

**Задание:**       
1. Определить текущий уровень выполнения (target).       
2. Просмотреть все доступные targets.       
3. Переключиться в multi-user.target (без графического интерфейса).       
4. Переключиться в graphical.target (с графическим интерфейсом).       
5. Установить графический интерфейс по умолчанию.       
6. Перезагрузить систему для применения изменений.       

**Решение и пояснения:**
```bash
systemctl get-default              # 1. Текущий target по умолчанию
ls -la /lib/systemd/system/*.target  # 2. Все доступные targets
sudo systemctl isolate multi-user.target  # 3. Переключение в консольный режим
sudo systemctl isolate graphical.target  # 4. Переключение в графический режим
sudo systemctl set-default graphical.target  # 5. Установка графического режима по умолчанию
sudo reboot                        # 6. Перезагрузка для проверки
```
**Пояснения:**        
В systemd традиционные runlevels заменены на targets.        
`multi-user.target` аналогичен runlevel 3 (многопользовательский без GUI).        
`graphical.target` — runlevel 5 (с GUI).        
`isolate` переключает немедленно, `set-default` устанавливает для последующих загрузок.        
Изменения вступают в силу после перезагрузки.

**Практическая работа №2: Управление загрузчиком GRUB**

**Задание:**       
1. Просмотреть текущую конфигурацию GRUB.       
2. Обновить конфигурацию GRUB после изменений.       
3. Установить задержку выбора ядра (таймаут) в 5 секунд.       
4. Добавить параметр загрузки ядра (например, `quiet`).       
5. Восстановить GRUB на основном диске.       
6. Загрузиться в однопользовательский режим (recovery).       

**Решение и пояснения:**
```bash
cat /etc/default/grub              # 1. Основная конфигурация GRUB
sudo update-grub                   # 2. Обновление конфигурации
sudo sed -i 's/GRUB_TIMEOUT=.*/GRUB_TIMEOUT=5/' /etc/default/grub  # 3. Изменение таймаута
sudo sed -i 's/GRUB_CMDLINE_LINUX_DEFAULT=".*"/& quiet/' /etc/default/grub  # 4. Добавление quiet
sudo update-grub                   # Применение изменений
sudo grub-install /dev/sda         # 5. Восстановление GRUB на диске sda
# 6. При загрузке: выбрать ядро → нажать e → добавить single в строку linux → Ctrl+X
```
**Пояснения:**        
`/etc/default/grub` — основной конфигурационный файл.        
`update-grub` генерирует финальный конфиг `/boot/grub/grub.cfg`.        
Параметр `quiet` скрывает вывод ядра при загрузке.        
`grub-install` устанавливает загрузчик на диск.        
Однопользовательский режим (`single`) позволяет выполнять восстановление без пароля.

**Практическая работа №3: Диагностика загрузки systemd**

**Задание:**       
1. Просмотреть журнал загрузки текущей сессии.       
2. Определить время загрузки системы.       
3. Найти службы, которые не смогли запуститься.       
4. Временно отключить службу от автозапуска.       
5. Включить автозапуск службы.       
6. Проверить зависимости между службами.       

**Решение и пояснения:**
```bash
sudo journalctl -b                 # 1. Логи текущей загрузки
systemd-analyze                    # 2. Время загрузки
systemd-analyze blame              # Детализация по службам
systemctl --failed                 # 3. Неудавшиеся службы
sudo systemctl disable service-name  # 4. Отключить автозапуск
sudo systemctl enable service-name   # 5. Включить автозапуск
systemctl list-dependencies multi-user.target  # 6. Зависимости target
```
**Пояснения:**        
`journalctl -b` показывает логи с момента последней загрузки.        
`systemd-analyze` анализирует время загрузки.        
`systemd-analyze blame` показывает время инициализации каждой службы.        
`disable`/`enable` управляют автозапуском.        
Зависимости показывают, какие службы должны запускаться до/после других.

**Практическая работа №4: Восстановление загрузки системы**       

**Задание:**       
1. Загрузиться с live-носителя.       
2. Смонтировать корневую файловую систему.       
3. Переустановить ядро и initramfs.       
4. Восстановить конфигурацию GRUB.       
5. Исправить поврежденный fstab.       
6. Проверить целостность загрузочных файлов.       

**Решение и пояснения:**       
```bash
# С live-носителя:
sudo mount /dev/sda1 /mnt           # 2. Монтирование корневой ФС
sudo mount /dev/sda2 /mnt/boot      # При отдельном /boot
sudo chroot /mnt                    # Переход в среду восстановления
apt install --reinstall linux-image-amd64  # 3. Переустановка ядра
update-initramfs -u -k all          # Обновление initramfs
grub-install /dev/sda               # 4. Восстановление GRUB
update-grub                         # Обновление конфига
nano /etc/fstab                     # 5. Исправление fstab
ls -la /boot/                       # 6. Проверка файлов
```
**Пояснения:**        
Live-носитель позволяет восстановить систему при проблемах с загрузкой.        
`chroot` переключает корневую ФС для работы в среде восстановленной системы.        
`update-initramfs` обновляет образ initramfs.        
Проверка `/boot/` на наличие `vmlinuz` (ядро) и `initrd.img` (initramfs).        
Важно правильно указать устройства в `/etc/fstab`.
