**Практическая работа №1: Локальная база паролей Samba**

**Задание:**
1. Посмотрите текущий backend паролей.
2. Добавьте локального пользователя Samba.
3. Список пользователей базы.
4. Задайте пароль пользователю.
5. Объясните разницу tdbsam/smbpasswd.

**Решение и пояснения:**
```bash
testparm -sv | grep passdb
sudo smbpasswd -a user1                   # 2. Добавление
sudo pdbedit -L                           # 3. Список
sudo smbpasswd user1                      # 4. Смена пароля
```
**Пояснения:**
Samba использует отдельную базу паролей. Backend `tdbsam` (по умолчанию) хранит данные в `passdb.tdb`; `smbpasswd` (устаревший) — в файле. `pdbedit` и `smbpasswd` управляют записями.

**Практическая работа №2: Синхронизация паролей**

**Задание:**
1. Установите модуль синхронизации PAM.
2. Настройте `pam_smbpass`.
3. Смените пароль пользователя и проверьте синхронизацию.
4. Проверьте вход Samba с новым паролем.
5. Объясните альтернативы синхронизации.

**Решение / Команды:**
```bash
# /etc/pam.d/common-password: pam_smbpass.so
sudo passwd user1
smbclient -L localhost -U user1
```
**Пояснения:**
`pam_smbpass` синхронизирует системный пароль с базой Samba при смене. Это удобно для standalone-серверов. Альтернатива — LDAP/AD как единый источник аутентификации.

**Практическая работа №3: Конвертация backend**

**Задание:**
1. Определите текущий backend.
2. Экспортируйте пользователей.
3. Переключите backend.
4. Импортируйте пользователей.
5. Проверьте работоспособность.

**Решение и пояснения:**
```bash
sudo pdbedit -Lw > /tmp/samba_users.bak   # 2. Экспорт
# smb.conf: passdb backend = tdbsam
sudo pdbedit -i smbpasswd:/tmp/samba_users.bak -e tdbsam   # 4. Импорт
sudo pdbedit -L                            # 5. Проверка
```
**Пояснения:**
`pdbedit -Lw` экспортирует базу, `-i` импортирует между backend-ами. Конвертация нужна при миграции с `smbpasswd` на `tdbsam` или LDAP. Перед конвертацией делают резервную копию.

**Практическая работа №4: Специальные и ограниченные учётные записи**

**Задание:**
1. Создайте системного пользователя без shell.
2. Создайте гостевую учётную запись.
3. Ограничьте пользователя (nologin, без пароля входа).
4. Настройте ресурс только для чтения.
5. Объясните принцип минимальных привилегий.

**Решение и пояснения:**
```bash
sudo useradd -M -s /usr/sbin/nologin svcuser
sudo smbpasswd -a svcuser
# smb.conf ресурс: read only = yes; valid users = svcuser
sudo pdbedit -L -v -u svcuser | grep -i "Account Flags"
```
**Пояснения:**
Служебные учётные записи создают без интерактивного shell (`nologin`) и с минимальными правами. Ресурсы для них делают только для чтения. Принцип минимальных привилегий снижает риск компрометации.
