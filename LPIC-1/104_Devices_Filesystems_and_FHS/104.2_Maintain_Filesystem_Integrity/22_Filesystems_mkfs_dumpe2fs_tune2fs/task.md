**Практическая работа №1: Создание и проверка файловых систем (mkfs, fsck)**

**Задание:**     
1. Определите свободный раздел (например, `/dev/sdb1`).     
2. Создайте на нем файловую систему ext4.     
3. Создайте файловую систему xfs (если доступна).     
4. Проверьте целостность файловой системы.     
5. Принудительно проверьте файловую систему даже если она «чистая».     
6. Смонтируйте созданную файловую систему.     

**Решение и пояснения:**
```bash
lsblk                                 # 1. Просмотр доступных разделов
sudo mkfs.ext4 /dev/sdb1              # 2. Создание файловой системы ext4
sudo apt install xfsprogs -y          # Установка утилит xfs
sudo mkfs.xfs /dev/sdb2               # 3. Создание XFS (если есть раздел)
sudo fsck /dev/sdb1                   # 4. Проверка ФС (только для размонтированных)
sudo fsck -f /dev/sdb1                # 5. Принудительная проверка
sudo mount /dev/sdb1 /mnt             # 6. Монтирование
```
**Пояснения:** 
`mkfs.ext4` создает файловую систему ext4.      
`mkfs.xfs` — для XFS.      
`fsck` проверяет и исправляет ошибки ФС, но ФС должна быть размонтирована.      
`-f` принуждает проверку даже если система помечена как чистая.      
Разные ФС имеют разные возможности и параметры по умолчанию.

**Практическая работа №2: Анализ информации о файловой системе (dumpe2fs)**     

**Задание:**     
1. Просмотрите общую информацию о файловой системе ext4.     
2. Найдите размер блока файловой системы.     
3. Определите количество свободных inodes.     
4. Просмотрите информацию о группах блоков.     
5. Сохраните полный вывод информации в файл.     
6. Сравните информацию с выводом `tune2fs -l`.     

**Решение и пояснения:**     
```bash
sudo dumpe2fs /dev/sdb1 | head -50   # 1. Первые 50 строк общей информации
sudo dumpe2fs /dev/sdb1 | grep "Block size"  # 2. Размер блока
sudo dumpe2fs /dev/sdb1 | grep "Free inodes" # 3. Свободные inodes
sudo dumpe2fs /dev/sdb1 | grep -A5 "Group" | head -20  # 4. Информация о группах
sudo dumpe2fs /dev/sdb1 > fs_info.txt # 5. Сохранение полной информации
sudo tune2fs -l /dev/sdb1             # 6. Альтернативный вывод информации
```
**Пояснения:**      
`dumpe2fs` показывает детальную информацию о ФС ext2/3/4.      
Размер блока влияет на производительность.      
Inodes ограничивают количество файлов.      
Группы блоков — единицы распределения пространства.      
`tune2fs -l` показывает похожую информацию, но в более структурированном виде.

**Практическая работа №3: Настройка параметров файловой системы (tune2fs)**     

**Задание:**     
1. Включите отложенное выделение inodes (lazy inode table initialization).     
2. Установите максимальное количество точек монтирования до проверки.     
3. Измените метку (label) файловой системы.     
4. Настройте интервал проверки ФС (раз в 30 дней).     
4. Добавьте резервную копию суперблока.     
5. Снимите флаг «прошла проверку» для принудительной проверки при следующей загрузке.     

**Решение и пояснения:**
```bash
sudo tune2fs -O ^uninit_bg /dev/sdb1  # 1. Отключить отложенную инициализацию (быстрее создание)
sudo tune2fs -c 10 /dev/sdb1          # 2. Проверять каждые 10 монтирований
sudo tune2fs -L DATA_PARTITION /dev/sdb1  # 3. Установка метки
sudo tune2fs -i 30d /dev/sdb1         # 4. Проверка раз в 30 дней
sudo tune2fs -O sparse_super /dev/sdb1 # 4.1. Разрешить дополнительные суперблоки
sudo tune2fs -C 20 /dev/sdb1          # 5. Установить счетчик монтирований (имитация)
```
**Пояснения:**      
`tune2fs` изменяет параметры ФС ext2/3/4.      
`-c N` — проверять каждые N монтирований.      
`-i Nd` — проверка по времени (d=дни, w=недели, m=месяцы).      
`-L` задает метку для удобной идентификации.      
`-C` устанавливает счетчик монтирований (для тестирования).      
Резервные суперблоки помогают при повреждениях.

**Практическая работа №4: Восстановление и отладка файловых систем**     

**Задание:**     
1. Найдите резервные копии суперблока.     
2. Попробуйте восстановить ФС с помощью резервного суперблока.     
3. Включите отладочный вывод при проверке ФС.     
4. Определите UUID файловой системы.     
5. Измените интервал проверки для уже смонтированной ФС.     
6. Создайте журнал изменений (journal) для ext3/4.     

**Решение и пояснения:**     
```bash
sudo mke2fs -n /dev/sdb1              # 1. Показать расположение суперблоков
sudo fsck -b 32768 /dev/sdb1          # 2. Использовать резервный суперблок (если основной поврежден)
sudo fsck -V /dev/sdb1                # 3. Подробный вывод (verbose)
sudo blkid /dev/sdb1                  # 4. Показать UUID и TYPE
sudo tune2fs -i 45d /dev/sdb1         # 5. Изменение интервала проверки (работает на смонтированной)
sudo tune2fs -O ^has_journal /dev/sdb1 # 6. Отключить журнал (для экономии ресурсов)
```
**Пояснения:**      
`mke2fs -n` показывает, где будут суперблоки, не создавая ФС.      
`fsck -b` использует резервный суперблок (номера из предыдущей команды).      
`blkid` показывает UUID, который используется в `/etc/fstab` вместо имени устройства.      
Журнал (journal) ускоряет восстановление после сбоев, но расходует немного ресурсов.      
Изменения `tune2fs` применяются сразу, кроме некоторых параметров, требующих размонтирования.
