**Практическая работа №1: Основы MTA**

**Задание:**
1. Установите простой MTA (`msmtp` или `postfix` в режиме «только отправка»).
2. Проверьте, какая программа отвечает за `sendmail`.
3. Отправьте тестовое письмо локальному пользователю.
4. Прочитайте почту локального пользователя.
5. Объясните роль MTA в системе.

**Решение и пояснения:**
```bash
sudo apt install -y mailutils postfix    # 1. MTA и клиент
which sendmail                           # 2. Эмуляция sendmail
echo "Тест" | mail -s "Subject" root     # 3. Отправка
mail                                     # 4. Чтение почты
```
**Пояснения:**
MTA (Mail Transfer Agent) — сервер пересылки почты: postfix, sendmail, exim. Команда `sendmail` часто является обёрткой (`sendmail emulation layer`). `mail` — простой почтовый клиент. Локальная почта складывается в `/var/mail/<user>`.

**Практическая работа №2: Алиасы почты**

**Задание:**
1. Откройте файл `/etc/aliases`.
2. Создайте алиас `admin` для пользователя `root`.
3. Создайте алиас для пересылки на внешний адрес.
4. Примените изменения через `newaliases`.
5. Проверьте работу алиаса.

**Решение и пояснения:**
```bash
sudo tee -a /etc/aliases >/dev/null <<'EOF'
admin: root
support: admin@example.com
EOF
sudo newaliases                          # 4. Перестроить базу алиасов
echo "test" | mail -s "alias test" admin # 5. Проверка
mailq                                    # Очередь писем
```
**Пояснения:**
`/etc/aliases` сопоставляет локальные имена получателей другим адресам. `newaliases` (или `postalias`) перестраивает базу алиасов после правки. Это используется для системных писем (root, postmaster).

**Практическая работа №3: Пересылка почты (~/.forward)**

**Задание:**
1. Создайте файл `~/.forward` для пользователя.
2. Настройте пересылку на другой адрес.
3. Проверьте синтаксис файла.
4. Отправьте письмо пользователю.
5. Объясните порядок обработки пересылки.

**Решение и пояснения:**
```bash
echo "user@example.com" > ~/.forward      # 2. Пересылка
cat ~/.forward                            # 3. Проверка
echo "forward test" | mail -s "test" $USER
```
**Пояснения:**
`~/.forward` задаёт пересылку почты для конкретного пользователя: одна строка с адресом (или команда `|program`, или файл). MTA сначала проверяет алиасы, затем `~/.forward` получателя. Пустой файл `.forward` блокирует пересылку.

**Практическая работа №4: Диагностика почты**

**Задание:**
1. Просмотрите очередь исходящих писем.
2. Найдите логи MTA.
3. Попробуйте отправить письмо на несуществующий домен.
4. Посмотрите причину задержки/отказа.
5. Объясните, где искать проблемы с почтой.

**Решение и пояснения:**
```bash
mailq                                    # 1. Очередь
sudo journalctl -u postfix -n 50         # 2. Логи postfix
echo "x" | mail -s "test" user@nonexistent.invalid   # 3
sudo tail -f /var/log/mail.log           # 4. Причина отказа
```
**Пояснения:**
`mailq` показывает письма в очереди. Логи MTA — в `/var/log/mail.log` и journal (`journalctl -u postfix`). Письма на несуществующий домен задерживаются и возвращаются (bounce) с кодом ошибки SMTP.
