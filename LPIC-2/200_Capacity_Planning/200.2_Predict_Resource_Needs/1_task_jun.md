**Практическая работа №1: Сбор исторических метрик**

**Задание:**
1. Проверьте, включён ли сбор статистики `sysstat`.
2. Посмотрите историческую загрузку CPU за сегодня.
3. Посмотрите историческое использование памяти.
4. Посмотрите исторический дисковый I/O.
5. Объясните, где хранятся данные sar.

**Решение и пояснения:**
```bash
systemctl status sysstat
sudo sed -i 's/^ENABLED=.*/ENABLED="true"/' /etc/default/sysstat
sudo systemctl restart sysstat
sar -u                          # 2. CPU за сегодня
sar -r                          # 3. Память
sar -d                          # 4. Диски
ls /var/log/sysstat/            # 5. Файлы saDD
```
**Пояснения:**
`sar` (пакет `sysstat`) собирает метрики по расписанию (cron) и хранит их в `/var/log/sysstat/`. `sar -u` — CPU, `-r` — память, `-d` — диски, `-n DEV` — сеть. Это основа для анализа трендов и планирования ёмкости.

**Практическая работа №2: Анализ тренда роста**

**Задание:**
1. Выберите метрику (например, использование диска).
2. Соберите значения за несколько дней.
3. Оцените скорость роста (в день).
4. Спрогнозируйте дату заполнения.
5. Объясните понятие точки исчерпания ресурса.

**Решение и пояснения:**
```bash
sar -r -f /var/log/sysstat/sa$(date +%d) | tail
df -h / | awk 'NR==2 {print $5}'
# Ручной расчёт:
# рост = (использование2 - использование1) / дни
# дней_до_100 = (100 - текущее) / рост
```
**Пояснения:**
Экстраполяция линейного роста позволяет предсказать исчерпание ресурса. Точка исчерпания (capacity break point) — момент, когда ресурс достигнет 100%. Регулярный сбор метрик и построение графиков (MRTG, Cacti, Grafana) делают прогноз точнее.

**Практическая работа №3: Мониторинг инфраструктуры**

**Задание:**
1. Установите лёгкий сборщик метрик `collectd`.
2. Включите сбор CPU и памяти.
3. Запустите службу.
4. Посмотрите собранные метрики.
5. Перечислите популярные системы мониторинга.

**Решение и пояснения:**
```bash
sudo apt install -y collectd
sudo systemctl enable --now collectd
ls /var/lib/collectd/            # 4. Файлы метрик (RRD)
```
**Пояснения:**
`collectd` — демон сбора метрик, часто используется с RRDtool/Grafana. Другие решения: Nagios/Icinga2 (алерты и проверки), MRTG (графики трафика SNMP), Cacti (графики на RRD), Prometheus + Grafana. Выбор зависит от масштаба и задач.

**Практическая работа №4: Практика планирования ёмкости**

**Задание:**
1. Определите текущее использование корневого раздела.
2. Найдите 5 крупнейших каталогов.
3. Оцените скорость роста `/var`.
4. Сделайте вывод о необходимости расширения.
5. Предложите меры (очистка, LVM, новый диск).

**Решение и пояснения:**
```bash
df -h /                              # 1. Использование
du -xhd1 /var 2>/dev/null | sort -h | tail -5   # 2. Крупные каталоги
du -sh /var/log                      # 3. Рост логов
journalctl --disk-usage              # 3. Объём журналов
```
**Пояснения:**
Планирование ёмкости начинается с инвентаризации: что занимает место и как быстро растёт. Решения: ротация логов (`logrotate`), очистка кэшей, расширение через LVM (`lvextend` + `resize2fs`), добавление диска. Прогноз роста помогает закупать ресурсы заранее.
