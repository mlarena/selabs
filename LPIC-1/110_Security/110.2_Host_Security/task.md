**Практическая работа №1: Теневые пароли**

**Задание:**
1. Посмотрите поля `/etc/passwd` и `/etc/shadow`.
2. Объясните, почему хэши паролей хранятся в `/etc/shadow`.
3. Проверьте права доступа к `/etc/shadow`.
4. Заблокируйте учётную запись (пароль `!`).
5. Разблокируйте учётную запись.

**Решение и пояснения:**
```bash
head -1 /etc/passwd                     # 1. Поля через :
sudo head -1 /etc/shadow                # 1. Хэш и сроки
ls -l /etc/shadow                       # 3. Права (640 root:shadow)
sudo passwd -l testuser                 # 4. Блокировка (символ !)
sudo passwd -u testuser                 # 5. Разблокировка
```
**Пояснения:**
`/etc/passwd` читаем всем и содержит учётные данные без пароля (поле `x`). Хэши — в `/etc/shadow`, доступном только root и группе shadow. `passwd -l` блокирует учётную запись, добавляя `!` перед хэшем.

**Практическая работа №2: Отключение неиспользуемых служб**

**Задание:**
1. Выведите список запущенных сетевых служб.
2. Найдите службы, слушающие порты.
3. Отключите ненужную службу.
4. Проверьте, что порт больше не слушается.
5. Объясните принцип минимального набора служб.

**Решение и пояснения:**
```bash
ss -tulpn                               # 1-2. Слушающие порты и процессы
systemctl list-units --type=service --state=running  # 1. Службы
sudo systemctl stop <service>           # 3. Остановка
sudo systemctl disable <service>        # 3. Отключение автозапуска
ss -tulpn | grep <port>                 # 4. Проверка
```
**Пояснения:**
Принцип минимизации: оставлять только необходимые службы. `ss -tulpn` показывает слушающие сокеты и связанные процессы. `systemctl stop`/`disable` останавливают службу и убирают её из автозапуска.

**Практическая работа №3: TCP Wrappers**

**Задание:**
1. Посмотрите файлы `/etc/hosts.allow` и `/etc/hosts.deny`.
2. Разрешите SSH только для одной подсети.
3. Запретите всё остальное.
4. Проверьте применение правил.
5. Объясните порядок обработки правил TCP Wrappers.

**Решение и пояснения:**
```bash
cat /etc/hosts.allow /etc/hosts.deny    # 1. Текущие правила
echo "sshd: 192.168.1.0/255.255.255.0" | sudo tee -a /etc/hosts.allow   # 2
echo "ALL: ALL" | sudo tee -a /etc/hosts.deny                            # 3
sudo systemctl restart ssh              # 4. Применение
```
**Пояснения:**
TCP Wrappers фильтрует доступ по имени хоста/IP. Сначала читается `hosts.allow` (разрешения), затем `hosts.deny` (запреты). Правило `ALL: ALL` в deny блокирует всё, кроме разрешённого в allow. В новых системах механизм устаревает в пользу firewall.

**Практическая работа №4: /etc/nologin и ограничение входа**

**Задание:**
1. Создайте файл `/etc/nologin` с сообщением.
2. Проверьте, что обычный пользователь не может войти.
3. Проверьте, что root может войти.
4. Удалите файл и восстановите вход.
5. Объясните, когда используют `/etc/nologin`.

**Решение и пояснения:**
```bash
echo "Система на обслуживании" | sudo tee /etc/nologin   # 1
su - testuser                                            # 2. Отказ входа
sudo -i                                                  # 3. root входит
sudo rm /etc/nologin                                     # 4. Восстановление
```
**Пояснения:**
`/etc/nologin` запрещает вход обычным пользователям (root может войти). Содержимое файла выводится как сообщение. Используется при обслуживании системы, чтобы предотвратить новые входы без остановки работающих сессий.
