**Практическая работа №1: Базовое монтирование и размонтирование**     

**Задание:**     
1. Создайте точку монтирования `/mnt/test`.     
2. Определите доступные файловые системы на устройстве (например, `/dev/sdb1`).     
3. Смонтируйте файловую систему ext4 в созданную точку.     
4. Проверьте успешность монтирования.     
5. Создайте тестовый файл в смонтированной файловой системе.     
6. Корректно размонтируйте файловую систему.     

**Решение и пояснения:**
```bash
sudo mkdir -p /mnt/test                     # 1. Создание точки монтирования
sudo blkid /dev/sdb1                        # 2. Определение типа ФС (если устройство существует)
sudo mount /dev/sdb1 /mnt/test              # 3. Монтирование (предполагаем ext4)
mount | grep /mnt/test                      # 4. Проверка: должна появиться запись
sudo touch /mnt/test/hello.txt              # 5. Создание файла для проверки
sudo umount /mnt/test                       # 6. Размонтирование
ls /mnt/test                                # Проверка: каталог должен быть пуст
```
**Пояснения:**      
`mkdir -p` создает каталог, если его нет.      
`blkid` показывает информацию о блочных устройствах, включая тип ФС.      
`mount` без параметров показывает все смонтированные ФС.      
`umount` (без "n") размонтирует.      
Важно размонтировать перед извлечением устройства.

**Практическая работа №2: Монтирование с различными опциями**     

**Задание:**     
1. Смонтируйте файловую систему в режиме «только для чтения» (ro).     
2. Смонтируйте с опцией, запрещающей выполнение файлов (noexec).     
3. Установите права на монтирование для обычного пользователя (опция uid).     
4. Проверьте влияние опций, попытавшись создать файл в ro-режиме.     
5. Перемонтируйте файловую систему с другими опциями «на лету».     
6. Смонтируйте образ диска (ISO-файл) как файловую систему.     

**Решение и пояснения:**     
```bash
sudo mount -o ro /dev/sdb1 /mnt/test       # 1. Только чтение
sudo mount -o remount,noexec /mnt/test     # 2. Запрет выполнения (или mount -o noexec ...)
sudo mount -o uid=$(id -u) /dev/sdb1 /mnt/test  # 3. Права для текущего пользователя
sudo touch /mnt/test/test.txt              # 4. Должна быть ошибка "Read-only file system"
sudo mount -o remount,rw /mnt/test         # 5. Изменение опций без размонтирования
sudo mount -o loop image.iso /mnt/iso      # 6. Монтирование ISO-образа
```
**Пояснения:**      
Опции монтирования задаются через `-o`.      
`ro`/`rw` — только чтение/чтение-запись.      
`noexec` запрещает запуск исполняемых файлов.      
`remount` позволяет изменить опции для уже смонтированной ФС.      
`-o loop` монтирует файл как блочное устройство.      
`uid` устанавливает владельца по умолчанию.

**Практическая работа №3: Работа с fstab и проверка зависимостей**     

**Задание:**     
1. Добавьте запись в `/etc/fstab` для автоматического монтирования.     
2. Проверьте корректность записи в fstab.     
3. Смонтируйте все файловые системы из fstab.     
4. Определите, какие файловые системы зависят от других (например, /home от /).     
5. Измените приоритет проверки fsck (последнее поле fstab).     
6. Удалите запись из fstab и размонтируйте.     

**Решение и пояснения:**     
```bash
echo "/dev/sdb1 /mnt/test ext4 defaults 0 2" | sudo tee -a /etc/fstab  # 1. Добавление записи
sudo mount -a                                 # 3. Монтирование всего из fstab
findmnt --real /mnt/test                     # 4. Показывает родительскую ФС
# В fstab изменить "0 2" на "0 1" для проверки раньше корневой ФС  # 5
sudo umount /mnt/test                        # 6. Размонтирование
sudo sed -i '/\/mnt\/test/d' /etc/fstab      # 6. Удаление записи (осторожно!)
```
**Пояснения:**      
Формат fstab: `<устройство> <точка> <тип> <опции> <dump> <pass>`.      
`mount -a` монтирует всё из fstab.      
`findmnt` показывает иерархию монтирования.      
Последнее поле (pass): 0 — не проверять, 1 — корневая ФС, 2 — остальные.      
Удаление из fstab предотвращает автоматическое монтирование при загрузке.

**Практическая работа №4: Монтирование сетевых файловых систем**     

**Задание:**     
1. Установите пакет для работы с CIFS (SMB).     
2. Создайте точку монтирования для сетевой шары.     
3. Смонтируйте сетевую папку по протоколу SMB/CIFS.     
4. Настройте монтирование с аутентификацией (логин/пароль).     
5. Проверьте доступ к файлам в смонтированной сетевой папке.     
6. Настройте автоматическое монтирование через fstab с credentials.     


**Решение и пояснения:**
```bash
sudo apt install cifs-utils                 # 1. Установка клиента CIFS
sudo mkdir /mnt/share                       # 2. Точка монтирования
sudo mount -t cifs //server/share /mnt/share -o username=user  # 3. Запрос пароля
# 4. С использованием файла учетных данных:
echo "username=user" > ~/smb.cred && echo "password=pass" >> ~/smb.cred
sudo mount -t cifs //server/share /mnt/share -o credentials=~/smb.cred
ls /mnt/share                               # 5. Проверка содержимого
# 6. В fstab: //server/share /mnt/share cifs credentials=/path/to/smb.cred 0 0
```
**Пояснения:**      
`cifs-utils` необходим для монтирования SMB/CIFS.      
`-t cifs` указывает тип ФС.      
Учетные данные можно передать через файл для безопасности.      
В fstab используйте `noauto`, если сеть не всегда доступна.      
Сетевые ФС зависят от сети, используйте `_netdev` в опциях fstab для правильного порядка загрузки.
