**Практическая работа №1: Базовые права доступа (chmod)**      

**Задание:**      
1. Создайте файл `secret.txt` и установите права только на чтение для владельца.      
2. Измените права, чтобы владелец мог читать и писать, группа — только читать, остальные — никаких прав.      
3. Добавьте право на выполнение для всех пользователей.      
4. Уберите право на запись для группы.      
5. Установите права числовым методом (например, 755).      
6. Проверьте текущие права файла.      

**Решение и пояснения:**
```bash
touch secret.txt                      # 1. Создание файла
chmod 400 secret.txt                  # 1. Только чтение для владельца (r--------)
chmod u=rw,g=r,o= secret.txt          # 2. Символьный метод: u=rwx,g=rx,o=
chmod a+x secret.txt                  # 3. Добавить выполнение для всех (a = all)
chmod g-w secret.txt                  # 4. Убрать запись для группы
chmod 755 secret.txt                  # 5. Числовой метод: rwxr-xr-x
ls -l secret.txt                      # 6. Проверка прав (первые 10 символов)
```
**Пояснения:**       
Права: r (read) = 4, w (write) = 2, x (execute) = 1.       
Символьный метод: `u` (user/владелец), `g` (group), `o` (others), `a` (all).       
Числовой метод: сумма значений (например, 7 = 4+2+1 = rwx).       
`ls -l` показывает права в виде `-rwxr-xr-x`.

**Практическая работа №2: Смена владельца и группы (chown, chgrp)**      

**Задание:**      
1. Создайте файл `report.txt` и проверьте его текущего владельца.      
2. Смените владельца файла на другого пользователя.      
3. Смените группу файла на `www-data`.      
4. Одновременно смените владельца и группу.      
5. Рекурсивно измените владельца для каталога и всего его содержимого.      
6. Восстановите исходного владельца файла.      

**Решение и пояснения:**      
```bash
touch report.txt
ls -l report.txt                      # 1. Проверка владельца и группы
sudo chown testuser report.txt        # 2. Смена владельца (требует sudo)
sudo chgrp www-data report.txt        # 3. Смена группы
sudo chown testuser:www-data report.txt  # 4. Одновременная смена
sudo chown -R testuser:testuser /path/to/directory  # 5. Рекурсивно для каталога
sudo chown $(whoami):$(id -gn) report.txt  # 6. Восстановление владельца
```
**Пояснения:**       
`chown` меняет владельца, `chgrp` — группу.       
Формат `user:group` меняет и то, и другое.       
`-R` (recursive) применяет изменения ко всем файлам и подкаталогам.       
`$(whoami)` возвращает текущего пользователя, `$(id -gn)` — его первичную группу.       
Только root может менять владельца произвольно.

**Практическая работа №3: Специальные биты (SUID, SGID, sticky bit)**      

**Задание:**      
1. Найдите файлы с установленным SUID-битом в `/usr/bin`.      
2. Установите SUID-бит на скрипт (владелец root).      
3. Установите SGID-бит на каталог.      
4. Установите sticky bit на каталог `/tmp/shared`.      
5. Проверьте установленные специальные биты.      
6. Удалите все специальные биты с файла.      

**Решение и пояснения:**      
```bash
find /usr/bin -type f -perm /4000 2>/dev/null | head -5  # 1. Поиск SUID
sudo chmod u+s /path/to/script.sh    # 2. Установка SUID (владелец должен быть root)
sudo chmod g+s /path/to/directory    # 3. Установка SGID на каталог
sudo mkdir /tmp/shared && sudo chmod +t /tmp/shared  # 4. Sticky bit
ls -ld /path/to/directory            # 5. Проверка: SUID (s в позиции владельца), SGID (s в группе), sticky (t в others)
chmod 0755 /path/to/file             # 6. Удаление всех специальных битов (0 в начале)
```
**Пояснения:**       
SUID (4xxx): файл выполняется с правами владельца.       
SGID (2xxx): файлы наследуют группу каталога.       
Sticky bit (1xxx): только владелец может удалять свои файлы в каталоге (например, 
`/tmp`). В `ls -l`: `s` вместо `x` у владельца/группы, `t` вместо `x` у others.

**Практическая работа №4: Маски и наследование прав (umask)**      

**Задание:**      
1. Проверьте текущую маску создания файлов.      
2. Создайте файл и каталог с текущей маской.      
3. Измените маску на 027 (пользователь — полные права, группа — чтение, остальные — ничего).      
4. Создайте файл и каталог с новой маской.      
5. Настройте постоянную маску для пользователя в `.bashrc`.      
6. Создайте скрипт, который создает файлы с правами 600 независимо от маски.      

**Решение и пояснения:**
```bash
umask                                 # 1. Текущая маска (обычно 022)
touch file1 && mkdir dir1            # 2. Права: файл 644, каталог 755 (при umask 022)
umask 027                            # 3. Установка новой маски
touch file2 && mkdir dir2            # 4. Права: файл 640, каталог 750
echo "umask 027" >> ~/.bashrc        # 5. Постоянная настройка
# 6. Скрипт create_secure.sh:
#!/bin/bash
touch "$1" && chmod 600 "$1"         # Создание файла и явная установка прав
```
**Пояснения:**       
Umask вычитается из максимальных прав (666 для файлов, 777 для каталогов).       
Например, umask 022 → файл: 666-022=644, каталог: 777-022=755. 
Umask 027 → файл: 666-027=640 (rw-r-----), каталог: 777-027=750 (rwxr-x---). 
Явное использование `chmod` переопределяет маску.
