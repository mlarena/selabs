**Практическая работа №1: Зависимости исполняемых файлов**

**Задание:**
1. Определите, от каких разделяемых библиотек зависит `/bin/ls`.
2. Найдите среди них библиотеку C (libc).
3. Выясните, какие библиотеки не найдены (если есть).
4. Определите зависимости `cat` без запуска самого файла.
5. Посмотрите версию libc, установленную в системе.

**Решение и пояснения:**
```bash
ldd /bin/ls                 # 1. Список зависимостей
ldd /bin/ls | grep libc     # 2. Библиотека libc.so.6
ldd /bin/ls | grep "not found"  # 3. Ненайденные библиотеки
objdump -p /bin/cat | grep NEEDED   # 4. Без запуска: секция NEEDED
ldd --version               # 5. Версия glibc
```
**Пояснения:**
`ldd` показывает, какие разделяемые библиотеки загружает программа. `objdump -p` безопаснее для недоверенных файлов, так как не запускает их. Строка `not found` означает отсутствующую библиотеку.

**Практическая работа №2: Поиск библиотеки и пакета**

**Задание:**
1. Найдите путь к библиотеке `libssl.so`.
2. Определите, какой установленный пакет предоставляет `/usr/lib/x86_64-linux-gnu/libc.so.6`.
3. Установите утилиту `apt-file` для поиска по содержимому пакетов.
4. Найдите пакет, который содержит файл `libpcre2-8.so`.
5. Выведите список файлов пакета `libssl3`.

**Решение и пояснения:**
```bash
ldconfig -p | grep libssl.so      # 1. Путь в кэше библиотек
dpkg -S /usr/lib/x86_64-linux-gnu/libc.so.6  # 2. Владелец файла
sudo apt install -y apt-file      # 3. Установка apt-file
sudo apt-file update              # 3. Обновление индекса
apt-file search libpcre2-8.so     # 4. Поиск пакета по файлу
dpkg -L libssl3 | head            # 5. Файлы пакета
```
**Пояснения:**
`ldconfig -p` выводит кэш разделяемых библиотек. `dpkg -S` ищет владельца файла среди установленных пакетов. `apt-file search` работает и для неустановленных пакетов. `dpkg -L` перечисляет файлы установленного пакета.

**Практическая работа №3: Настройка пути поиска библиотек**

**Задание:**
1. Создайте каталог `/opt/mylibs`.
2. Скопируйте туда какую-нибудь библиотеку (например, `libc.so.6`).
3. Добавьте каталог в конфигурацию динамического компоновщика.
4. Обновите кэш библиотек.
5. Проверьте, что каталог попал в кэш.

**Решение и пояснения:**
```bash
sudo mkdir -p /opt/mylibs
sudo cp /usr/lib/x86_64-linux-gnu/libc.so.6 /opt/mylibs/
echo "/opt/mylibs" | sudo tee /etc/ld.so.conf.d/mylibs.conf   # 3. Конфиг
sudo ldconfig                       # 4. Обновление кэша
ldconfig -p | grep /opt/mylibs      # 5. Проверка
```
**Пояснения:**
Динамический компоновщик ищет библиотеки по путям из `/etc/ld.so.conf` и `/etc/ld.so.conf.d/*.conf`. После изменения конфигурации нужно выполнить `ldconfig`, чтобы перестроить кэш `/etc/ld.so.cache`.

**Практическая работа №4: Переменная LD_LIBRARY_PATH**

**Задание:**
1. Поместите тестовую библиотеку в `/opt/testlib`.
2. Не добавляя её в конфигурацию, проверьте, что программа её не видит.
3. Укажите путь через переменную окружения.
4. Проверьте, что библиотека теперь найдена.
5. Объясните, почему `LD_LIBRARY_PATH` не рекомендуется использовать постоянно.

**Решение и пояснения:**
```bash
sudo mkdir -p /opt/testlib
sudo cp /usr/lib/x86_64-linux-gnu/libz.so.1 /opt/testlib/
ldd /bin/ls | grep /opt/testlib      # 2. Пусто - не видит
export LD_LIBRARY_PATH=/opt/testlib  # 3. Временный путь поиска
ldd /bin/ls | grep /opt/testlib      # 4. Может быть найден
unset LD_LIBRARY_PATH
```
**Пояснения:**
`LD_LIBRARY_PATH` задаёт дополнительные каталоги поиска библиотек на время сессии. Постоянное использование небезопасно (риск подмены библиотек и конфликтов версий), поэтому системные пути задают через `ld.so.conf`. Сброс — `unset`.
