# Экзаменационные боевые задачи — Тема 200: Capacity Planning

Задачи приближены к реальным заданиям экзамена **201-450**.

## Задача 1. Диагностика нехватки ресурсов

**Условие:** Сервер стал медленным. Определите, какой ресурс (CPU, RAM, диск, I/O) является узким местом.

**Ожидаемый результат:** Выявлен исчерпанный ресурс.

**Решение и пояснения:**
```bash
top -bn1 | head -20
free -h
vmstat 1 5
iostat -x 1 3
df -h ; df -i
sar -u 1 3
```
`vmstat` показывает очереди и swap, `iostat -x` — загрузку дисков (%util, await), `free` — память, `df -i` — inodes. Узкое место — ресурс с максимальной загрузкой/очередью.

## Задача 2. Анализ памяти и swap

**Условие:** Определите, что память утекает, найдите процесс-виновника и оцените использование swap.

**Ожидаемый результат:** Процесс найден.

**Решение и пояснения:**
```bash
ps aux --sort=-%mem | head
smem -rs rss 2>/dev/null || echo "установите smem"
cat /proc/meminfo | grep -E "MemAvailable|SwapUsed"
sudo pmap -x <PID> | tail
vmstat -s
```
`ps --sort=-%mem` находит прожорливые процессы, `pmap` — карту памяти, `/proc/meminfo` — общую статистику. Постоянный рост RSS указывает на утечку.

## Задача 3. Прогнозирование потребностей

**Условие:** Соберите историческую статистику загрузки и спрогнозируйте необходимость расширения.

**Ожидаемый результат:** Данные собраны, прогноз сформулирован.

**Решение и пояснения:**
```bash
sar -u -f /var/log/sysstat/sa$(date +%d)   # История CPU
sar -r -f /var/log/sysstat/sa$(date +%d)   # История памяти
sar -d -f /var/log/sysstat/sa$(date +%d)   # История дисков
ls /var/log/sysstat/
```
`sysstat` собирает историю (sar). Анализ трендов (рост CPU/памяти/диска) позволяет прогнозировать. Планирование — по пиковым и средним значениям с запасом.

## Задача 4. Мониторинг дискового пространства

**Условие:** Найдите каталоги, занимающие больше всего места, и настройте оповещение о заполнении.

**Ожидаемый результат:** Крупные каталоги найдены, оповещение настроено.

**Решение и пояснения:**
```bash
du -h --max-depth=1 / | sort -hr | head
ncdu /var 2>/dev/null || echo "установите ncdu"
# Скрипт-оповещение через cron:
# df -h | awk '$5+0 > 80 {print}' | mail -s "Disk alert" admin
```
`du`/`ncdu` находят крупные каталоги. Оповещение через cron при заполнении >80% предотвращает отказ. Важно следить и за inodes (`df -i`).

## Задача 5. Нагрузочное тестирование и планирование

**Условие:** Опишите методику оценки ёмкости: как определить, сколько запросов выдержит сервер.

**Ожидаемый результат:** Предложена методика.

**Решение и пояснения:**
```bash
sudo apt install -y apache2-utils
ab -n 1000 -c 50 http://localhost/          # Нагрузочный тест
sudo apt install -y sysstat
sar -n DEV 1 5                               # Сетевой трафик
```
Нагрузочные тесты (`ab`, wrk, JMeter) измеряют пропускную способность. Ёмкость планируют по: CPU, памяти, дисковому I/O, сети. Ориентир — держать загрузку ≤70% в пике.
