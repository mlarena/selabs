# Экзаменационные боевые задачи — Тема 102: Linux Installation and Package Management

Задачи приближены к реальным заданиям экзамена **101-500**.

## Задача 1. Планирование разметки диска

**Условие:** Спроектируйте разметку диска для сервера: отдельные разделы для `/`, `/home`, `/var`, `/boot` и swap 2 ГБ.

**Ожидаемый результат:** Предложена схема разделов с обоснованием размеров.

**Решение и пояснения:**
```text
/boot  1G  (ядро и загрузчик)
/      20G (система)
/var   20G (логи, БД — отдельный раздел защищает / от переполнения)
/home  остаток (данные пользователей)
swap   2G  (или = RAM при гибернации)
```
Отдельные разделы изолируют рост данных. `/var` отделяют из-за логов, `/home` — из-за данных пользователей. Swap нужен для гибернации и нехватки RAM.

## Задача 2. Установка загрузчика

**Условие:** Установите GRUB в MBR диска `/dev/sda` и настройте меню загрузки.

**Ожидаемый результат:** GRUB установлен, конфигурация обновлена.

**Решение и пояснения:**
```bash
sudo grub-install /dev/sda
sudo update-grub
cat /boot/grub/grub.cfg | head
# Настройки меню: /etc/default/grub (GRUB_TIMEOUT, GRUB_DEFAULT)
sudo update-grub
```
`grub-install` записывает загрузчик, `update-grub` генерирует `grub.cfg` из шаблонов и `grub.d`. Настройки меню — в `/etc/default/grub`.

## Задача 3. Работа с общими библиотеками

**Условие:** Программа не запускается: «error while loading shared libraries». Найдите и устраните проблему.

**Ожидаемый результат:** Программа запускается.

**Решение и пояснения:**
```bash
ldd /path/to/program             # Найти недостающую библиотеку
sudo ldconfig -p | grep <lib>    # Есть ли библиотека в кэше
echo "/opt/lib" | sudo tee /etc/ld.so.conf.d/opt.conf
sudo ldconfig                    # Обновить кэш
```
`ldd` показывает зависимости, `ldconfig` обновляет кэш (`/etc/ld.so.cache`). Пути к библиотекам задают в `/etc/ld.so.conf.d/`. Переменная `LD_LIBRARY_PATH` — временное решение.

## Задача 4. Управление пакетами Debian

**Условие:** Установите пакет, найдите пакет по файлу, удалите пакет с конфигурацией, добавьте репозиторий.

**Ожидаемый результат:** Все операции выполнены успешно.

**Решение и пояснения:**
```bash
sudo apt install -y nginx
dpkg -S /usr/sbin/nginx          # Какому пакету принадлежит файл
apt-cache show nginx | head
sudo apt purge nginx             # Удаление с конфигурацией
sudo add-apt-repository ppa:... ; sudo apt update
```
`apt` управляет пакетами из репозиториев, `dpkg` — низкоуровнево. `apt purge` удаляет и конфиги, `dpkg -S` ищет владельца файла, `apt-cache` показывает метаданные.

## Задача 5. Работа с RPM/YUM (awareness)

**Условие:** Опишите, как выполнить те же операции в RPM-системе (RHEL/CentOS).

**Ожидаемый результат:** Приведены эквивалентные команды.

**Решение и пояснения:**
```bash
sudo yum install nginx
rpm -qf /usr/sbin/nginx          # Владелец файла
rpm -ql nginx                    # Список файлов пакета
sudo yum remove nginx
rpm -qa | grep nginx
```
RPM-системы используют `yum`/`dnf` (высокоуровнево) и `rpm` (низкоуровнево), аналогично `apt`/`dpkg`. Репозитории — в `/etc/yum.repos.d/`.

## Задача 6. Linux как гость виртуализации

**Условие:** Определите, что система работает в виртуальной машине, и установите гостевые утилиты.

**Ожидаемый результат:** Тип гипервизора определён, утилиты установлены.

**Решение и пояснения:**
```bash
systemd-detect-virt
sudo dmidecode -s system-product-name
sudo apt install -y qemu-guest-agent
sudo systemctl enable --now qemu-guest-agent
```
`systemd-detect-virt` определяет гипервизор (kvm, vmware, virtualbox). Гостевые утилиты улучшают интеграцию (время, сеть, управление). `dmidecode` показывает производителя платформы.
