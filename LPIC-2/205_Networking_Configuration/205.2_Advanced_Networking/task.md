**Практическая работа №1: Анализ состояния сетевых устройств**

**Задание:**
1. Посмотрите статистику интерфейсов.
2. Найдите ошибки и потери пакетов.
3. Проверьте состояние линка.
4. Посмотрите скорость и дуплекс.
5. Объясните показатели RX/TX.

**Решение и пояснения:**
```bash
ip -s link show eth0                 # 1-2. Статистика и ошибки
ethtool eth0                         # 3-4. Скорость, дуплекс, линк
ethtool -S eth0 | grep -i error      # 2. Драйверные счётчики
```
**Пояснения:**
`ip -s link` показывает пакеты, байты и ошибки. `ethtool` — параметры линка (скорость, duplex, autoneg). Ошибки/дропы указывают на проблемы кабеля, дуплекса или перегрузку.

**Практическая работа №2: Захват и анализ трафика**

**Задание:**
1. Захватите 10 пакетов на интерфейсе.
2. Отфильтруйте трафик по порту.
3. Отфильтруйте по хосту.
4. Сохраните захват в файл.
5. Прочитайте сохранённый файл.

**Решение и пояснения:**
```bash
sudo tcpdump -i eth0 -c 10                       # 1. Первые 10 пакетов
sudo tcpdump -i eth0 port 22                     # 2. Фильтр по порту
sudo tcpdump -i eth0 host 8.8.8.8                # 3. Фильтр по хосту
sudo tcpdump -i eth0 -w /tmp/cap.pcap            # 4. Сохранение
sudo tcpdump -r /tmp/cap.pcap -nn                # 5. Чтение
```
**Пояснения:**
`tcpdump` — консольный анализатор трафика (libpcap). Фильтры BPF позволяют выбирать пакеты по порту, хосту, протоколу. `-w` пишет pcap-файл, который открывают в Wireshark для детального анализа.

**Практическая работа №3: Сканирование и тестирование портов**

**Задание:**
1. Проверьте доступность TCP-порта.
2. Просканируйте распространённые порты на хосте.
3. Определите версии служб.
4. Просканируйте подсеть на наличие узлов.
5. Объясните этические ограничения сканирования.

**Решение и пояснения:**
```bash
nc -zv 192.168.1.10 80                  # 1. Проверка порта
nmap -sT 192.168.1.10                   # 2. TCP-скан портов
nmap -sV 192.168.1.10                   # 3. Версии служб
nmap -sn 192.168.1.0/24                 # 4. Скан подсети (ping)
```
**Пояснения:**
`nc -z` проверяет открытость порта, `nmap` сканирует диапазоны и определяет службы. Сканировать можно только свои сети или при наличии письменного разрешения: несанкционированное сканирование незаконно.

**Практическая работа №4: Диагностика соединений**

**Задание:**
1. Посмотрите все TCP-соединения.
2. Найдите соединения в состоянии TIME_WAIT.
3. Посмотрите, какой процесс слушает порт.
4. Проверьте, кто использует порт.
5. Объясните состояния TCP.

**Решение и пояснения:**
```bash
ss -tan                                 # 1. TCP-соединения
ss -tan state time-wait                 # 2. TIME_WAIT
sudo ss -tlnp                           # 3. Слушающие порты и процессы
sudo lsof -i :80                        # 4. Кто использует порт
```
**Пояснения:**
`ss` заменяет `netstat`. Состояния TCP: LISTEN, ESTABLISHED, TIME_WAIT (после закрытия), CLOSE_WAIT и др. Множество TIME_WAIT — норма после интенсивных коротких соединений. `lsof -i` показывает процессы, использующие порт.
