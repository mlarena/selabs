**Практическая работа №1: Базовое добавление записи в fstab**      

**Задание:**      
1. Определите UUID вашего раздела (например, `/dev/sdb1`).      
2. Создайте точку монтирования `/mnt/data`.      
3. Добавьте запись в `/etc/fstab` для автоматического монтирования при загрузке.      
4. Протестируйте запись с помощью `mount -a`.      
5. Перезагрузите систему и проверьте, что раздел смонтировался автоматически.      
6. Измените опции монтирования на `noauto` и проверьте результат.      

**Решение и пояснения:**
```bash
sudo blkid /dev/sdb1                  # 1. Определение UUID раздела
sudo mkdir /mnt/data                  # 2. Создание точки монтирования
echo "UUID=ваш-uuid /mnt/data ext4 defaults 0 2" | sudo tee -a /etc/fstab  # 3. Добавление записи
sudo mount -a                         # 4. Тестирование записи (ошибок быть не должно)
sudo reboot                           # 5. Перезагрузка
df -h | grep /mnt/data                # После перезагрузки проверьте наличие раздела
sudo nano /etc/fstab                  # 6. Измените defaults на noauto,defaults
sudo umount /mnt/data && sudo mount -a  # Раздел не должен смонтироваться
```

**Пояснения:**       
Использование UUID предпочтительнее имени устройства, так как UUID постоянен.       
Формат записи: `<устройство> <точка> <тип_фс> <опции> <dump> <pass>`.       
`mount -a` монтирует все из fstab.       
Опция `noauto` отключает автоматическое монтирование при загрузке,       
но позволяет монтировать вручную или через `mount -a`.

**Практическая работа №2: Работа с различными типами файловых систем в fstab**      

**Задание:**      
1. Добавьте запись для монтирования сетевой шары NFS.      
2. Добавьте запись для монтирования раздела Windows (NTFS/FAT32).      
3. Настройте монтирование временной файловой системы (tmpfs).      
4. Добавьте запись для монтирования раздела с флагами `noexec,nosuid`.      
5. Проверьте все записи с помощью `mount -a`.      
6. Исправьте ошибку в fstab (искусственно добавьте неверную запись).      

**Решение и пояснения:**      
```bash
# 1. NFS (предположим, сервер 192.168.1.100 экспортирует /shared):
echo "192.168.1.100:/shared /mnt/nfs nfs defaults 0 0" | sudo tee -a /etc/fstab

# 2. NTFS (требует пакет ntfs-3g):
echo "/dev/sdc1 /mnt/win ntfs-3g defaults,uid=1000,gid=1000 0 0" | sudo tee -a /etc/fstab

# 3. tmpfs (оперативная память):
echo "tmpfs /mnt/ram tmpfs size=512M,mode=1777 0 0" | sudo tee -a /etc/fstab

# 4. Безопасное монтирование:
echo "UUID=ваш-uuid /mnt/secure ext4 defaults,noexec,nosuid 0 2" | sudo tee -a /etc/fstab

sudo mount -a                         # 5. Тестирование
sudo nano /etc/fstab                  # 6. Добавьте строку с ошибкой, затем исправьте
```
**Пояснения:**       
Для NFS нужен доступ к серверу.       
Для NTFS требуется пакет `ntfs-3g`.       
`uid/gid` задают владельца для Windows разделов.       
tmpfs создает ФС в оперативной памяти.       
Опции `noexec,nosuid` повышают безопасность, запрещая выполнение файлов и установку SUID/SGID битов.

**Практическая работа №3: Продвинутые опции монтирования и приоритеты**      

**Задание:**
1. Настройте монтирование с отложенной записью (lazy).      
2. Установите квоты на файловую систему через fstab.      
3. Настройте порядок проверки ФС при загрузке (поле pass).      
4. Добавьте опцию `_netdev` для сетевых файловых систем.      
5. Настройте монтирование с кодировкой для FAT32.      
6. Создайте резервную копию fstab и восстановите ее.      

**Решение и пояснения:**      
```bash
# 1. Отложенная запись (не рекомендуется для USB-накопителей):
echo "UUID=ваш-uuid /mnt/data ext4 defaults,lazytime 0 2" | sudo tee -a /etc/fstab

# 2. Включение квот:
echo "UUID=ваш-uuid /mnt/data ext4 defaults,usrquota,grpquota 0 2" | sudo tee -a /etc/fstab

# 3. Порядок проверки: 1 для корневой ФС, 2 для остальных, 0 - не проверять

# 4. Сетевая ФС с ожиданием сети:
echo "//server/share /mnt/smb cifs credentials=/etc/samba/credentials,_netdev 0 0" | sudo tee -a /etc/fstab

# 5. FAT32 с кодировкой:
echo "/dev/sdd1 /mnt/usb vfat defaults,iocharset=utf8 0 0" | sudo tee -a /etc/fstab

sudo cp /etc/fstab /etc/fstab.backup   # 6. Резервная копия
# Восстановление: sudo cp /etc/fstab.backup /etc/fstab
```
**Пояснения:**       
`lazytime` откладывает обновление времени модификации файлов.       
Квоты включаются опциями `usrquota,grpquota`.       
`_netdev` гарантирует, что монтирование произойдет после подключения сети.       
`iocharset=utf8` корректно отображает русские имена на FAT32.       
Всегда делайте резервную копию перед редактированием fstab!

**Практическая работа №4: Диагностика и устранение проблем с fstab**      

**Задание:**      
1. Создайте ошибку в fstab (неверный UUID).      
2. Попробуйте выполнить `mount -a` и проанализируйте ошибку.      
3. Войдите в recovery mode для исправления ошибки.      
4. Исправьте ошибку, используя только командную строку.      
5. Восстановите работоспособность системы.      
6. Напишите скрипт для проверки синтаксиса fstab.      

**Решение и пояснения:**      
```bash
# 1. Добавьте неверную запись:
echo "UUID=неверный-uuid /mnt/bad ext4 defaults 0 2" | sudo tee -a /etc/fstab

sudo mount -a                         # 2. Получите ошибку "bad UUID"

# 3-4. Если система не загружается:
# - Выберите recovery mode в загрузчике
# - Смонтируйте корневую ФС в режиме RW: mount -o remount,rw /
# - Исправьте fstab: nano /etc/fstab
# - Перезагрузитесь: reboot

# 5. Удалите ошибочную строку:
sudo sed -i '/неверный-uuid/d' /etc/fstab

# 6. Скрипт проверки:
#!/bin/bash
sudo mount -a 2>&1 | grep -i "error\|fail" || echo "fstab в порядке"
```
**Пояснения:**       
При ошибках в fstab система может не загрузиться.       
Recovery mode позволяет исправить это.       
`mount -o remount,rw /` перемонтирует корневую ФС в режиме записи.       
Всегда проверяйте fstab командой `mount -a` перед перезагрузкой.       
Скрипт проверки можно добавить в cron для регулярного мониторинга.
