**Практическая работа №1: Базовый анализ открытых портов**

**Задание:**      
1. Установите утилиту `net-tools` для работы с сетью.      
2. Покажите все открытые TCP-порты на локальной машине.      
3. Покажите все открытые UDP-порты.      
4. Отфильтруйте вывод, чтобы показать только слушающие (LISTEN) порты.      
5. Определите, какие порты открыты на localhost (127.0.0.1).      
6. Покажите числовые адреса вместо имен служб.      

**Решение и пояснения:**
```bash
sudo apt install net-tools -y   # 1. Установка net-tools
netstat -tln                    # 2. Все TCP порты в состоянии LISTEN (-l)
netstat -uln                    # 3. Все UDP порты
netstat -tlnp                   # 4. С процессами (-p) и именами служб (-n)
netstat -tln | grep 127.0.0.1   # 5. Портs на localhost
netstat -tln                    # 6. -n показывает числовые адреса
```
**Пояснения:**       
`netstat` показывает сетевые соединения.       
`-t` — TCP, 
`-u` — UDP, 
`-l` — слушающие порты, 
`-n` — числовой формат, 
`-p` — PID/имя процесса. Состояние LISTEN означает, что порт открыт и ожидает подключений.

**Практическая работа №2: Современный анализ портов (ss)**

**Задание:**      
1. Используйте современную утилиту `ss` для анализа портов.      
2. Покажите все TCP-порты в состоянии LISTEN.      
3. Покажите UDP-порты.      
4. Определите процессы, слушающие порты (с именами).      
5. Найдите, какой процесс использует порт 22 (SSH).      
6. Проверьте порты, открытые для всех интерфейсов (не только localhost).      

**Решение и пояснения:**
```bash
ss -tln                         # 1,2. TCP порты LISTEN (современная замена netstat)
ss -uln                         # 3. UDP порты
ss -tlpn                        # 4. С именами процессов (-p)
ss -tlpn | grep :22             # 5. Кто слушает порт 22
ss -tln | grep -v 127.0.0.1     # 6. Порты не на localhost
```
**Пояснения:**       
`ss` быстрее и современнее `netstat`.       
`-t` — TCP,       
`-u` — UDP,       
`-l` — слушающие,              
`-n` — числовой формат,              
`-p` — процессы.              
Вывод показывает Local Address — на каком интерфейсе и порту слушает процесс.

**Практическая работа №3: Связь портов с процессами**

**Задание:**        
1. Найдите все процессы, слушающие сетевые порты.        
2. Определите полный путь к исполняемому файлу для процесса на порту 80.        
3. Проверьте, какие порты открывает конкретный процесс (например, `sshd`).        
4. Узнайте пользователя, от которого запущен процесс на порту.        
5. Найдите необычные/неизвестные процессы, слушающие порты.        
6. Создайте отчет о всех сетевых сервисах.        

**Решение и пояснения:**
```bash
sudo lsof -i -P -n | grep LISTEN  # 1. Все слушающие процессы с lsof
sudo lsof -i:80                   # 2. Процесс на порту 80
sudo ss -tlpn | grep sshd         # 3. Порты процесса sshd
sudo lsof -i -P -n | grep LISTEN | awk '{print $1,$3,$9}'  # 4. Процесс, пользователь, порт
sudo netstat -tlnp | grep -vE "(ssh|apache|nginx|mysql)"  # 5. Нестандартные процессы
sudo ss -tulpn > network_services.txt  # 6. Отчет
```

**Пояснения:**         
`lsof` показывает открытые файлы (включая сетевые сокеты).         
`-i` — сетевые соединения,         
`-P` — не преобразовывать порты в имена,         
`-n` — числовые адреса.         
`grep -vE` исключает известные сервисы.         
Важно проверять незнакомые процессы на нестандартных портах.

**Практическая работа №4: Проверка безопасности и фильтрация**

**Задание:**        
1. Проверьте, какие порты доступны извне (не только localhost).        
2. Найдите порты, открытые на всех интерфейсах (0.0.0.0 или ::).        
3. Проверьте, нет ли открытых портов в нестандартных диапазонах (>1024).        
4. Определите, какие порты должны быть закрыты (например, 21/FTP если не используется).        
5. Создайте скрипт для регулярной проверки открытых портов.        
6. Настройте оповещение при появлении новых слушающих портов.        

**Решение и пояснения:**
```bash
ss -tln | grep -v 127.0.0.1 | grep -v ::1  # 1. Порты не на localhost
ss -tln | grep '0.0.0.0'                  # 2. Порты на всех интерфейсах
ss -tln | awk '{print $4}' | awk -F: '{print $NF}' | sort -nu | grep -E '^(1[0-9]{3}|[2-9][0-9]{3}|[1-5][0-9]{4}|6[0-5][0-9]{3})'  # 3. Высокие порты
sudo netstat -tlnp | grep :21             # 4. Проверка FTP порта (21)
# 5. Скрипт check_ports.sh:
ss -tuln > /tmp/current_ports.txt
diff /tmp/previous_ports.txt /tmp/current_ports.txt  # 6. Сравнение с предыдущим состоянием
```
**Пояснения:**         
Порт 0.0.0.0 означает "все интерфейсы".         
Порты >1024 — не привилегированные, часто используются приложениями.         
Регулярная проверка помогает обнаружить неавторизованные сервисы.         
Сравнение `diff` показывает изменения в открытых портах.
