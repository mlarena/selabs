**Практическая работа №1: Просмотр параметров загрузки ядра**

**Задание:**
1. Просмотрите параметры, с которыми загрузилось текущее ядро.
2. Определите, какой init (система инициализации) используется.
3. Проверьте, установлен ли параметр `quiet` в текущей загрузке.
4. Узнайте, какой корневой раздел используется.
5. Определите, передавался ли параметр `single` при загрузке.
6. Сохраните текущие параметры ядра в файл для анализа.

**Решение и пояснения:**
```bash
cat /proc/cmdline                    # 1. Все параметры текущей загрузки
cat /proc/1/comm                     # 2. Проверка init (systemd или init)
grep -q "quiet" /proc/cmdline && echo "Тихий режим включен" || echo "Тихий режим выключен"  # 3
grep -o "root=[^ ]*" /proc/cmdline   # 4. Корневой раздел
grep -q "single" /proc/cmdline && echo "Загружено в single режиме" || echo "Обычная загрузка"  # 5
cat /proc/cmdline > kernel_params_$(date +%Y%m%d).txt  # 6. Сохранение
```
**Пояснения:** `/proc/cmdline` — виртуальный файл, содержащий параметры командной строки, переданные ядру при загрузке. Параметр `root=` указывает, где находится корневая файловая система. `quiet` подавляет большинство сообщений ядра. `single` загружает систему в однопользовательском режиме.

**Практическая работа №2: Изменение параметров ядра через GRUB**

**Задание:**
1. Отредактируйте конфигурацию GRUB для добавления параметров ядра.
2. Добавьте параметр `nomodeset` для отключения переключения видеорежимов.
3. Добавьте параметр `maxcpus=1` для ограничения количества ядер процессора.
4. Удалите параметр `quiet` для отображения всех сообщений загрузки.
5. Примените изменения и перезагрузитесь.
6. Проверьте, что новые параметры применились.

**Решение и пояснения:**
```bash
sudo nano /etc/default/grub          # 1. Редактирование конфига GRUB
# Найдите строку GRUB_CMDLINE_LINUX_DEFAULT и измените:
GRUB_CMDLINE_LINUX_DEFAULT="nomodeset maxcpus=1"  # 2,3. Добавление параметров
# Уберите quiet из строки (если был)           # 4. Удаление quiet
sudo update-grub                      # 5. Обновление конфигурации GRUB
sudo reboot                           # Перезагрузка
cat /proc/cmdline                     # 6. Проверка новых параметров
```
**Пояснения:** Параметры ядра добавляются в переменные `GRUB_CMDLINE_LINUX` (для всех записей) и `GRUB_CMDLINE_LINUX_DEFAULT` (только для обычной загрузки). `nomodeset` полезен при проблемах с графическим драйвером. `maxcpus=1` ограничивает использование многоядерности (для отладки). После изменений обязательно выполните `update-grub`.

**Практическая работа №3: Временные параметры ядра при загрузке**

**Задание:**
1. Перезагрузите систему и войдите в меню GRUB.
2. Выберите запись ядра и нажмите 'e' для редактирования.
3. Найдите строку, начинающуюся с `linux` или `linux16`.
4. Добавьте параметр `init=/bin/bash` в конец строки.
5. Загрузитесь с этими параметрами (Ctrl+X или F10).
6. Проанализируйте результат (попадание в bash без запуска systemd).

**Решение и пояснения:**
```bash
# 1-3. Действия в загрузчике:
# При появлении меню GRUB выбрать нужную запись, нажать 'e'
# Найти строку, начинающуюся с 'linux' (например, linux /vmlinuz-... root=... ro)
# 4. Перейти в конец строки и добавить: init=/bin/bash
# Должно получиться: ... ro quiet init=/bin/bash
# 5. Нажать Ctrl+X или F10 для загрузки с этими параметрами
# 6. В результате вы попадете в bash с правами root, но корневая ФС смонтирована как read-only
mount -o remount,rw /                # Перемонтирование корня в RW для внесения изменений
```
**Пояснения:** Временное редактирование в GRUB действует только для текущей загрузки. Параметр `init=/bin/bash` заменяет стандартную систему инициализации (systemd) на bash. Это мощный способ восстановления системы при проблемах с загрузкой, не требующий знания пароля root.

**Практическая работа №4: Диагностические и отладочные параметры**

**Задание:**
1. Добавьте параметр `debug` для включения отладочной информации ядра.
2. Добавьте параметр `loglevel=7` для максимальной детализации логов.
3. Добавьте параметр `panic=10` для автоматической перезагрузки при kernel panic.
4. Проверьте уровень логирования после загрузки.
5. Измените уровень логирования на лету (без перезагрузки).
6. Проанализируйте журнал загрузки с новыми параметрами.

**Решение и пояснения:**
```bash
sudo nano /etc/default/grub
# Добавьте параметры:
GRUB_CMDLINE_LINUX_DEFAULT="debug loglevel=7 panic=10"
sudo update-grub && sudo reboot

# 4. Проверка текущего уровня логирования
cat /proc/sys/kernel/printk        # Показывает текущий уровень (первое число)
# 5. Изменение уровня логирования на лету
echo 8 | sudo tee /proc/sys/kernel/printk

# 6. Просмотр детальных логов загрузки
sudo journalctl -b | grep -i "kernel" | head -20
# Или старые логи ядра:
dmesg | head -20
```
**Пояснения:** Параметр `debug` включает дополнительную отладочную информацию. `loglevel` устанавливает порог важности сообщений, выводимых на консоль (от 0 до 7, где 7 — максимальная детализация). `panic=10` заставит систему перезагрузиться через 10 секунд после kernel panic. Уровень логирования можно менять через `/proc/sys/kernel/printk`.
