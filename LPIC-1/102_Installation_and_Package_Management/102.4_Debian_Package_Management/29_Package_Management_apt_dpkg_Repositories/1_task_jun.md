**Практическая работа №1: Базовое управление пакетами через apt**      

**Задание:**       
1. Обновить список доступных пакетов.       
2. Установить пакет `htop`.       
3. Обновить все установленные пакеты до последних версий.       
4. Удалить пакет `htop`, оставив конфигурационные файлы.       
5. Полностью удалить пакет со всеми конфигурационными файлами.       
6. Найти пакет по имени (например, содержащий `nginx`).       

**Решение и пояснения:**
```bash
sudo apt update                    # 1. Обновление списка пакетов из репозиториев
sudo apt install htop              # 2. Установка пакета
sudo apt upgrade                   # 3. Обновление установленных пакетов
sudo apt remove htop               # 4. Удаление пакета (конфиги остаются)
sudo apt purge htop                # 5. Полное удаление с конфигами
apt search nginx                   # 6. Поиск пакета в репозиториях
```
**Пояснения:**        
`apt update` обновляет локальную базу данных пакетов.        
`apt upgrade` обновляет установленные пакеты.        
Разница между `remove` и `purge`: `purge` удаляет также конфигурационные файлы.        
`apt search` ищет по имени и описанию пакета.

**Практическая работа №2: Работа с пакетами .deb через dpkg**       

**Задание:**       
1. Установить пакет из локального .deb файла.       
2. Проверить, установлен ли пакет (например, `curl`).       
3. Просмотреть информацию об установленном пакете.       
4. Просмотреть список файлов, которые принадлежат пакету.       
5. Удалить пакет, но оставить конфигурационные файлы.       
6. Восстановить поврежденные зависимости пакетов.       

**Решение и пояснения:**
```bash
sudo dpkg -i package.deb           # 1. Установка локального .deb файла
dpkg -l | grep curl                # 2. Проверка установки
dpkg -s curl                       # 3. Информация о пакете
dpkg -L curl                       # 4. Список файлов пакета
sudo dpkg -r curl                  # 5. Удаление пакета (конфиги остаются)
sudo apt install -f                # 6. Исправление зависимостей
```
**Пояснения:**        
`dpkg` работает с локальными .deb файлами, но не разрешает зависимости автоматически.        
`dpkg -l` показывает все установленные пакеты.        
`dpkg -s` показывает статус и информацию.        
`dpkg -L` показывает файлы, установленные пакетом.        
`apt install -f` исправляет сломанные зависимости после установки через dpkg.

**Практическая работа №3: Управление репозиториями**

**Задание:**       
1. Просмотреть список всех настроенных репозиториев.       
2. Добавить репозиторий вручную через командную строку.       
3. Добавить репозиторий через `add-apt-repository`.       
4. Обновить список пакетов после добавления репозитория.       
5. Удалить репозиторий.       
6. Просмотреть содержимое репозитория (доступные пакеты).       

**Решение и пояснения:**
```bash
cat /etc/apt/sources.list          # 1. Основной файл репозиториев
ls /etc/apt/sources.list.d/        # 1. Дополнительные файлы репозиториев
echo "deb http://repo.example.com/debian stable main" | sudo tee -a /etc/apt/sources.list  # 2. Ручное добавление
sudo add-apt-repository ppa:ondrej/php  # 3. Добавление PPA репозитория
sudo apt update                    # 4. Обновление списка пакетов
sudo add-apt-repository --remove ppa:ondrej/php  # 5. Удаление репозитория
apt-cache search package-name      # 6. Поиск пакета в репозиториях
```
**Пояснения:**        
Репозитории хранятся в `/etc/apt/sources.list` и файлах в `/etc/apt/sources.list.d/`.        
PPA (Personal Package Archive) — репозитории для Ubuntu, могут работать на Debian после настройки.        
После добавления репозитория обязательно нужно выполнить `apt update`.        
`apt-cache search` ищет пакеты в доступных репозиториях.

**Практическая работа №4: Расширенные операции с пакетами**

**Задание:**       
1. Просмотреть историю операций с пакетами.       
2. Установить конкретную версию пакета.       
3. Заблокировать версию пакета от обновления.       
4. Просмотреть зависимости пакета.       
5. Скачать пакет без установки.       
6. Очистить кэш загруженных пакетов.       

**Решение и пояснения:**       
```bash
cat /var/log/apt/history.log       # 1. История операций apt
sudo apt install package=1.2.3-1   # 2. Установка конкретной версии
sudo apt-mark hold package         # 3. Блокировка обновления пакета
apt-cache depends package          # 4. Просмотр зависимостей
sudo apt download package          # 5. Скачивание .deb файла
sudo apt clean                     # 6. Полная очистка кэша пакетов
sudo apt autoclean                 # Удаление устаревших пакетов из кэша
```
**Пояснения:**        
`/var/log/apt/history.log` содержит историю команд apt.        
Указание версии через `=`.        
`apt-mark hold` предотвращает обновление пакета.        
`apt-cache depends` показывает зависимости.        
`apt download` скачивает .deb файл в текущую директорию.        
`apt clean` удаляет все скачанные .deb файлы,        
`autoclean` удаляет только те, которые больше недоступны в репозиториях.
