**Практическая работа №1: Основы DFS**

**Задание:**
1. Объясните назначение DFS.
2. Включите поддержку DFS в Samba.
3. Создайте DFS-корень.
4. Создайте DFS-ссылку.
5. Проверьте работу ссылки.

**Решение и пояснения:**
```bash
# smb.conf: host msdfs = yes
sudo mkdir -p /srv/samba/dfs
# smb.conf:
# [dfs] path=/srv/samba/dfs msdfs root=yes
sudo ln -s "msdfs:server\\docs" /srv/samba/dfs/docs
sudo systemctl reload smbd
smbclient //localhost/dfs -U user1 -c "ls"
```
**Пояснения:**
DFS (Distributed File System) объединяет ресурсы разных серверов в единое дерево. `host msdfs = yes` включает поддержку, `msdfs root = yes` делает ресурс корнем DFS. Ссылки — симлинки вида `msdfs:server\share`.

**Практическая работа №2: DFS-прокси**

**Задание:**
1. Объясните назначение DFS-прокси.
2. Настройте `msdfs proxy`.
3. Проверьте перенаправление.
4. Сравните DFS-корень и прокси.
5. Объясните сценарии использования.

**Решение и пояснения:**
```bash
# smb.conf:
# [legacy] msdfs proxy = \\newserver\\docs
sudo systemctl reload smbd
smbclient //localhost/legacy -U user1 -c "ls"
```
**Пояснения:**
`msdfs proxy` перенаправляет подключения к ресурсу на другой сервер/ресурс. Это удобно при миграции: клиенты продолжают обращаться по старому имени, а данные уже на новом сервере.

**Практическая работа №3: Проверка DFS и устранение проблем**

**Задание:**
1. Проверьте конфигурацию DFS.
2. Посмотрите журнал Samba на предмет DFS.
3. Проверьте, что ссылки являются симлинками.
4. Проверьте доступ к целевому ресурсу.
5. Объясните типовые ошибки.

**Решение и пояснения:**
```bash
testparm -sv | grep -i msdfs
ls -l /srv/samba/dfs/
sudo grep -i dfs /var/log/samba/log.smbd | tail
smbclient //target/docs -U user1 -c "ls"
```
**Пояснения:**
DFS-ссылки — симлинки с префиксом `msdfs:`. Ошибки: отсутствие `host msdfs`, неверный путь ссылки, недоступность целевого сервера, проблемы прав. Проверка — через `smbclient` и логи.

**Практическая работа №4: Масштабирование файловых ресурсов**

**Задание:**
1. Объясните роль DFS в масштабировании.
2. Настройте namespace для нескольких серверов.
3. Обеспечьте единообразие прав.
4. Проверьте доступность при отказе сервера (концептуально).
5. Объясните ограничения Samba DFS.

**Решение и пояснения:**
```bash
# Дерево: /srv/samba/dfs/{docs,projects,hr}
# Ссылки на разные серверы:
# ln -s "msdfs:fs1\\docs" /srv/samba/dfs/docs
# ln -s "msdfs:fs2\\projects" /srv/samba/dfs/projects
```
**Пояснения:**
DFS создаёт единое пространство имён поверх множества серверов, упрощая доступ и миграцию. Ограничение: Samba DFS не поддерживает все расширения Windows DFS (репликация namespace), поэтому в крупных средах применяют Windows DFS-R или сторонние решения.
