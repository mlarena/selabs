# Экзаменационные боевые задачи — Тема 104: Devices, Linux Filesystems, FHS

Задачи приближены к реальным заданиям экзамена **101-500**.

## Задача 1. Создание разделов и файловых систем

**Условие:** На новом диске `/dev/sdb` создайте раздел, отформатируйте его в ext4 и смонтируйте.

**Ожидаемый результат:** Раздел создан, отформатирован, смонтирован.

**Решение и пояснения:**
```bash
sudo fdisk /dev/sdb          # n -> p -> +5G -> w
sudo partprobe /dev/sdb
sudo mkfs.ext4 /dev/sdb1
sudo mkdir -p /mnt/data
sudo mount /dev/sdb1 /mnt/data
df -h /mnt/data
```
`fdisk` создаёт таблицу разделов, `partprobe` перечитывает её, `mkfs.ext4` форматирует. После монтирования раздел доступен как каталог.

## Задача 2. Поддержание целостности ФС

**Условие:** Проверьте ФС на ошибки и настройте автоматическую проверку при загрузке.

**Ожидаемый результат:** ФС проверена, параметры настроены.

**Решение и пояснения:**
```bash
sudo umount /mnt/data
sudo e2fsck -f /dev/sdb1
sudo tune2fs -c 30 /dev/sdb1       # Проверка каждые 30 монтирований
sudo dumpe2fs -h /dev/sdb1 | head
sudo mount /dev/sdb1 /mnt/data
```
`e2fsck` проверяет и восстанавливает ФС (только на размонтированной). `tune2fs` задаёт частоту проверок, `dumpe2fs` показывает суперблок.

## Задача 3. Управление монтированием и fstab

**Условие:** Настройте постоянное монтирование раздела по UUID с проверкой.

**Ожидаемый результат:** Раздел монтируется автоматически.

**Решение и пояснения:**
```bash
blkid /dev/sdb1                      # Получить UUID
# /etc/fstab: UUID=<uuid> /mnt/data ext4 defaults 0 2
sudo findmnt --verify
sudo mount -a
findmnt /mnt/data
```
UUID надёжнее имени устройства. `findmnt --verify` проверяет fstab, `mount -a` монтирует все записи. Поле `0 2` — dump и порядок fsck.

## Задача 4. Права доступа и владение

**Условие:** Создайте общий каталог для группы `devs`: члены группы пишут, остальные читают; новые файлы наследуют группу.

**Ожидаемый результат:** Каталог настроен согласно требованиям.

**Решение и пояснения:**
```bash
sudo mkdir -p /srv/shared
sudo chown root:devs /srv/shared
sudo chmod 2750 /srv/shared          # setgid + rwxr-x---
sudo setfacl -m g:devs:rwx /srv/shared   # При необходимости ACL
ls -ld /srv/shared                   # drwxr-s---
```
setgid на каталоге (`2xxx`) заставляет новые файлы наследовать группу каталога. ACL дополняет базовые права.

## Задача 5. Жёсткие и символические ссылки

**Условие:** Создайте жёсткую и символическую ссылку, объясните различия и удалите исходный файл.

**Ожидаемый результат:** Различия продемонстрированы.

**Решение и пояснения:**
```bash
echo "data" > file.txt
ln file.txt hard.txt        # Жёсткая ссылка (тот же inode)
ln -s file.txt soft.txt     # Символическая ссылка
ls -li file.txt hard.txt soft.txt
rm file.txt
cat hard.txt    # Работает
cat soft.txt    # Ошибка: битая ссылка
```
Жёсткая ссылка указывает на тот же inode (данные живы, пока есть ссылки). Симлинк хранит путь и ломается при удалении цели. Жёсткие ссылки не работают между ФС и для каталогов.

## Задача 6. Поиск файлов и FHS

**Условие:** Найдите все файлы больше 100 МБ, изменённые за последние 7 дней, и файлы с setuid-битом.

**Ожидаемый результат:** Найдены нужные файлы.

**Решение и пояснения:**
```bash
find / -type f -size +100M -mtime -7 2>/dev/null
find / -perm -4000 -type f 2>/dev/null
sudo updatedb && locate nginx.conf
man hier                              # Описание FHS
```
`find` ищет по размеру, времени, правам. `locate` использует БД (`updatedb`), быстрее `find`. `man hier` описывает иерархию ФС.
