**Практическая работа №1: Информация о ядре и модулях**

**Задание:**
1. Получите информацию о работающем ядре.
2. Посмотрите параметры загрузки ядра.
3. Выведите список модулей с размерами.
4. Получите параметры конкретного модуля.
5. Объясните файл `modules.dep`.

**Решение и пояснения:**
```bash
uname -a                                   # 1. Версия и сборка
cat /proc/cmdline                          # 2. Параметры загрузки
lsmod                                      # 3. Модули и размеры
modinfo -p e1000                           # 4. Параметры модуля
head /lib/modules/$(uname -r)/modules.dep  # 5. Зависимости
```
**Пояснения:**
`/proc/cmdline` содержит параметры, переданные ядру загрузчиком. `modules.dep` описывает зависимости модулей и создаётся `depmod`. `modinfo -p` показывает принимаемые модулем параметры.

**Практическая работа №2: Загрузка и выгрузка модулей вручную**

**Задание:**
1. Загрузите модуль с параметром.
2. Проверьте, что модуль загружен.
3. Выгрузите модуль.
4. Настройте автозагрузку модуля при старте.
5. Объясните, когда модуль можно выгрузить.

**Решение и пояснения:**
```bash
sudo modprobe dummy numdummies=2           # 1. Загрузка с параметром
lsmod | grep dummy                         # 2. Проверка
ls /sys/module/dummy/parameters/           # 2. Параметры
sudo rmmod dummy                           # 3. Выгрузка
echo "dummy" | sudo tee /etc/modules-load.d/dummy.conf   # 4. Автозагрузка
echo "options dummy numdummies=2" | sudo tee /etc/modprobe.d/dummy.conf  # 4
```
**Пояснения:**
Модуль можно выгрузить, если его счётчик использования равен 0 (модуль не используется). Автозагрузка настраивается в `/etc/modules-load.d/`, параметры — в `/etc/modprobe.d/`. Зависимости обновляет `depmod`.

**Практическая работа №3: udev и горячее подключение**

**Задание:**
1. Пронаблюдайте события udev в реальном времени.
2. Подключите устройство и посмотрите событие.
3. Посмотрите правила udev.
4. Создайте правило для сетевого интерфейса.
5. Примените и проверьте правило.

**Решение и пояснения:**
```bash
udevadm monitor                            # 1. События в реальном времени
udevadm info --query=all --name=/dev/sda   # 2. Информация об устройстве
ls /etc/udev/rules.d/                      # 3. Правила
echo 'SUBSYSTEM=="net", ACTION=="add", ATTR{address}=="aa:bb:cc:dd:ee:ff", NAME="lan0"' | \
  sudo tee /etc/udev/rules.d/70-lan0.rules   # 4. Правило
sudo udevadm control --reload && sudo udevadm trigger   # 5. Применение
```
**Пояснения:**
udev управляет устройствами в `/dev` и реагирует на горячее подключение. `udevadm monitor` показывает события, `udevadm info` — атрибуты. Правила в `/etc/udev/rules.d/` задают имена, права и действия для устройств.

**Практическая работа №4: Параметры ядра через sysctl**

**Задание:**
1. Посмотрите значение параметра ядра.
2. Измените параметр временно.
3. Сделайте параметр постоянным.
4. Примените файл настроек.
5. Объясните разницу между `/proc/sys` и sysctl.

**Решение и пояснения:**
```bash
sysctl net.ipv4.ip_forward                          # 1. Текущее значение
sudo sysctl -w net.ipv4.ip_forward=1                # 2. Временно
echo "net.ipv4.ip_forward=1" | sudo tee /etc/sysctl.d/99-forward.conf   # 3
sudo sysctl --system                                # 4. Применить всё
cat /proc/sys/net/ipv4/ip_forward                   # 5. Прямое чтение
```
**Пояснения:**
`/proc/sys` — интерфейс к параметрам ядра. `sysctl` читает/пишет их удобнее. Временные изменения сбрасываются при перезагрузке; постоянные задают в `/etc/sysctl.conf` и `/etc/sysctl.d/*.conf`. `sysctl --system` применяет все файлы.
