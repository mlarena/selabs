**Практическая работа №1: Ручная настройка сети через iproute2**     

**Задание:**     
1. Определите имена сетевых интерфейсов.     
2. Настройте статический IP-адрес на интерфейсе.     
3. Добавьте шлюз по умолчанию.     
4. Настройте DNS-серверы.     
5. Проверьте сетевое соединение.     
6. Сбросьте настройки к DHCP.     

**Решение и пояснения:**
```bash
ip link show                          # 1. Показать все интерфейсы
sudo ip addr add 192.168.1.100/24 dev eth0  # 2. Добавить IP (замените eth0)
sudo ip route add default via 192.168.1.1  # 3. Добавить шлюз
echo "nameserver 8.8.8.8" | sudo tee /etc/resolv.conf  # 4. Добавить DNS
ping -c 3 8.8.8.8                     # 5. Проверить связность
sudo dhclient eth0                    # 6. Получить настройки по DHCP (если демон работает)
```
**Пояснения:**      
`ip addr add` добавляет IP-адрес, но не включает интерфейс (для включения: `sudo ip link set eth0 up`).      
`ip route add default` задает шлюз по умолчанию.      
`/etc/resolv.conf` может быть перезаписан сетевыми менеджерами.      
Настройки через `ip` временные (до перезагрузки).

**Практическая работа №2: Настройка сети через NetworkManager (nmcli)**

**Задание:**
1. Проверьте состояние NetworkManager.     
2. Просмотрите список сетевых подключений.     
3. Создайте новое подключение со статическим IP.     
4. Активируйте созданное подключение.     
5. Измените параметры существующего подключения.     
6. Удалите созданное подключение.     

**Решение и пояснения:**     
```bash
systemctl status NetworkManager       # 1. Проверка состояния службы
nmcli connection show                 # 2. Список подключений
nmcli connection add con-name "static-eth0" ifname eth0 type ethernet ip4 192.168.1.100/24 gw4 192.168.1.1  # 3. Создание
nmcli connection up "static-eth0"    # 4. Активация
nmcli connection modify "static-eth0" ipv4.dns "8.8.8.8 8.8.4.4"  # 5. Добавление DNS
nmcli connection down "static-eth0" && nmcli connection delete "static-eth0"  # 6. Удаление
```
**Пояснения:**      
`nmcli` — клиент командной строки для NetworkManager.      
Подключения сохраняются и переживают перезагрузку.      
`connection add` создает,      
`modify` изменяет параметры.           
`con-name` — имя подключения,      
`ifname` — физический интерфейс.           
NetworkManager автоматически обновляет `/etc/resolv.conf`.

**Практическая работа №3: Маршрутизация и таблицы маршрутов**

**Задание:**     
1. Просмотрите таблицу маршрутизации.     
2. Добавьте статический маршрут к конкретной сети.     
3. Удалите статический маршрут.          
4. Проверьте маршрут до конкретного хоста.     
5. Измените метрику маршрута.     
6. Сохраните маршруты для восстановления после перезагрузки.     

**Решение и пояснения:**
```bash
ip route show                         # 1. Показать таблицу маршрутизации
sudo ip route add 10.0.0.0/24 via 192.168.1.1  # 2. Добавить маршрут к сети 10.0.0.0/24
sudo ip route del 10.0.0.0/24 via 192.168.1.1  # 3. Удалить маршрут
ip route get 8.8.8.8                  # 4. Показать маршрут до конкретного адреса
sudo ip route add default via 192.168.1.1 metric 100  # 5. Добавить шлюз с метрикой
# 6. Для сохранения маршрутов добавьте в /etc/network/interfaces:
# up ip route add 10.0.0.0/24 via 192.168.1.1
```
**Пояснения:**      
Таблица маршрутизации определяет, куда отправлять пакеты.      
`ip route add` добавляет маршрут.      
Метрика определяет приоритет маршрута (меньше = лучше).      
Маршруты, добавленные через `ip`, не сохраняются после перезагрузки.      
Для постоянных маршрутов используйте конфигурационные файлы или NetworkManager.

**Практическая работа №4: Диагностика и устранение проблем сети**     

**Задание:**     
1. Проверьте доступность хоста с помощью ping.     
2. Определите, где обрывается связь (traceroute).     
3. Проверьте открытые порты на локальной машине.     
4. Проанализируйте сетевой трафик на интерфейсе.     
5. Сбросьте настройки сетевого интерфейса.     
6. Восстановите сеть после сбоя.     

**Решение и пояснения:**     
```bash
ping -c 4 google.com                  # 1. Проверка связности (или ping IP)
traceroute google.com                 # 2. Трассировка маршрута (или tracepath)
ss -tuln | head -10                   # 3. Проверка открытых портов
sudo tcpdump -i eth0 -c 5             # 4. Просмотр 5 пакетов на интерфейсе
sudo ip link set eth0 down && sudo ip link set eth0 up  # 5. Перезапуск интерфейса
sudo systemctl restart NetworkManager  # 6. Перезапуск сетевого менеджера
# Или: sudo dhclient -r eth0 && sudo dhclient eth0  # Обновление DHCP
```
**Пояснения:**      
`ping` проверяет доступность.      
`traceroute` показывает путь пакетов.      
`ss` показывает открытые порты и соединения.      
`tcpdump` — сниффер для анализа трафика.      
Перезапуск интерфейса или NetworkManager часто решает временные проблемы.      
При проблемах с DHCP используйте `dhclient` для получения нового адреса.
