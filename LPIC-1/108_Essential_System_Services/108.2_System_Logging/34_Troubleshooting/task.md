**Практическая работа №1: Диагностика проблем с загрузкой системы**     

**Задание:**     
1. Система не загружается, показывает ошибку "Kernel panic".     
2. Определите причину проблемы.     
3. Восстановите работоспособность системы.     
4. Проверьте целостность файлов ядра.     
5. Переустановите поврежденные пакеты.     
6. Создайте резервный образ ядра.     

**Решение и пояснения:**
```bash
# 1-2. Загрузитесь с live-носителя и проверьте
sudo fsck -y /dev/sda1            # Проверка корневой файловой системы
# 3. Смонтируйте корневую ФС и переустановите ядро
sudo mount /dev/sda1 /mnt
sudo chroot /mnt
apt install --reinstall linux-image-$(uname -r)
update-initramfs -u
# 4. Проверка целостности ядра
ls -la /boot/vmlinuz-*
# 5. Проверка поврежденных пакетов
dpkg -l | grep ^..r
# 6. Создание резервного образа
cp /boot/vmlinuz-$(uname -r) /boot/vmlinuz-backup
```
**Пояснения:**      
Kernel panic часто вызван повреждением файловой системы или ядра.      
`fsck` проверяет и исправляет ошибки ФС.      
Переустановка ядра восстанавливает поврежденные файлы.      
Резервная копия ядра полезна для быстрого восстановления.

**Практическая работа №2: Проблемы с дисковым пространством**     

**Задание:**     
1. Система сообщает "No space left on device".     
2. Определите, какой раздел переполнен.     
3. Найдите большие файлы и директории.     
4. Очистите временные файлы и кэши.     
5. Освободите место, удалив старые логи.     
6. Настройте мониторинг свободного места.     

**Решение и пояснения:**
```bash
# 1-2. Проверка свободного места
df -h                              # Показать использование дисков
# 3. Поиск больших файлов
sudo find / -type f -size +100M 2>/dev/null | head -10
# 4. Очистка временных файлов
sudo apt clean                    # Очистка кэша apt
sudo rm -rf /tmp/*
# 5. Очистка старых логов
sudo find /var/log -name "*.log" -mtime +30 -delete
# 6. Настройка мониторинга
echo "df -h" > /usr/local/bin/check_space && chmod +x /usr/local/bin/check_space
```
**Пояснения:**      
`df -h` показывает использование дисков.      
`find -size +100M` ищет файлы больше 100MB.      
Очистка кэша apt и временных файлов часто освобождает значительное пространство.      
Регулярная чистка логов предотвращает переполнение.

**Практическая работа №3: Проблемы с сетевым подключением**     

**Задание:**     
1. Нет сетевого подключения.     
2. Проверьте состояние сетевых интерфейсов.     
3. Проверьте маршрутизацию и DNS.     
4. Перезапустите сетевые службы.     
5. Сбросьте сетевые настройки.     
6. Проверьте наличие блокировок брандмауэром.     

**Решение и пояснения:**     
```bash     
# 1-2. Проверка интерфейсов
ip link show                      # Статус интерфейсов
ip addr show                      # IP адреса
# 3. Проверка сетевой связности
ping -c 3 8.8.8.8                 # Проверка доступа в интернет
nslookup google.com               # Проверка DNS
# 4. Перезапуск сетевых служб
sudo systemctl restart networking
# 5. Сброс настроек
sudo dhclient -r eth0 && sudo dhclient eth0
# 6. Проверка брандмауэра
sudo iptables -L -n               # Показать правила iptables
```
**Пояснения:**      
`ip link show` показывает состояние интерфейсов (UP/DOWN).      
Если ping до IP работает, но DNS нет — проблема в DNS.      
`dhclient` обновляет DHCP аренду. iptables может блокировать трафик.

**Практическая работа №4: Проблемы с пакетами и зависимостями**     

**Задание:**     
1. Ошибка "Could not get lock /var/lib/dpkg/lock".     
2. Ошибка "Unmet dependencies".     
3. Восстановите поврежденную базу пакетов.     
4. Удалите конфликтующие пакеты.     
5. Восстановите конфигурационные файлы.     
6. Проверьте целостность установленных пакетов.     

**Решение и пояснения:**     
```bash
# 1. Ошибка блокировки
sudo rm /var/lib/dpkg/lock        # Удаление блокировки
sudo dpkg --configure -a          # Завершение прерванных операций
# 2. Неразрешенные зависимости
sudo apt --fix-broken install
# 3. Восстановление базы
sudo apt update --fix-missing
# 4. Удаление конфликтующих пакетов
sudo dpkg --remove --force-remove-reinstreq package_name
# 5. Восстановление конфигов
sudo dpkg-reconfigure package_name
# 6. Проверка целостности
debsums -c 2>/dev/null | head -10
```
**Пояснения:**      
Блокировка возникает при параллельном запуске apt/dpkg.      
`--fix-broken` исправляет зависимости.      
`dpkg-reconfigure` восстанавливает конфиги.      
`debsums` проверяет контрольные суммы файлов пакетов.

**Практическая работа №5: Проблемы с правами доступа**     

**Задание:**     
1. Ошибка "Permission denied" при запуске скрипта.     
2. Невозможно удалить файл "Operation not permitted".     
3. Восстановите стандартные права на системные файлы.     
4. Найдите файлы с нестандартными владельцами.     
5. Исправьте права на исполняемые файлы.     
6. Проверьте наличие SUID/SGID файлов.     

**Решение и пояснения:**
```bash
# 1. Исправление прав на скрипт
chmod +x script.sh
# 2. Проверка атрибутов файла
lsattr file.txt                   # Показывает атрибуты
sudo chattr -i file.txt           # Снимает атрибут неизменяемости
# 3. Восстановление стандартных прав
sudo dpkg-statoverride --list     # Показать переопределения прав
# 4. Поиск файлов с нестандартными владельцами
find / -nouser -o -nogroup 2>/dev/null | head -10
# 5. Исправление прав
sudo chmod 755 /usr/local/bin/*
# 6. Проверка SUID/SGID
find / -type f -perm /6000 2>/dev/null | head -10
```
**Пояснения:**      
`chattr` управляет атрибутами файлов (например, `+i` делает неизменяемым).      
`dpkg-statoverride` показывает измененные права пакетов.      
Файлы без владельца могут быть признаком проблем.

**Практическая работа №6: Проблемы с процессом и памятью**     

**Задание:**     
1. Система работает медленно, зависает.     
2. Определите процессы, потребляющие много ресурсов.     
3. Завершите зависшие процессы.     
4. Проверьте использование памяти и swap.     
5. Очистите кэш памяти.     
6. Настройте ограничения для процессов.     

**Решение и пояснения:**     
```bash
# 1-2. Мониторинг процессов
top                                # Интерактивный мониторинг
ps aux --sort=-%mem | head -10    # Топ по памяти
# 3. Завершение процессов
kill -9 PID                        # Принудительное завершение
pkill process_name                 # Завершение по имени
# 4. Проверка памяти
free -h                            # Память и swap
# 5. Очистка кэша
echo 3 | sudo tee /proc/sys/vm/drop_caches  # Очистка кэша страниц
# 6. Ограничения
ulimit -a                          # Показать текущие лимиты
```
**Пояснения:**      
`top` показывает нагрузку в реальном времени.      
`kill -9` принудительно завершает процесс.      
Очистка кэша памяти может временно ускорить систему.      
`ulimit` задает ограничения ресурсов для процессов.

**Практическая работа №7: Проблемы с файловой системой**

**Задание:**     
1. Ошибка "Input/output error" при доступе к файлам.     
2. Файловая система доступна только для чтения.     
3. Проверьте файловую систему на ошибки.     
4. Восстановите поврежденные файлы.     
5. Перемонтируйте файловую систему в режим чтения-записи.     
6. Проверьте диск на битые сектора.     

**Решение и пояснения:**
```bash
# 1-2. Проверка состояния ФС
dmesg | tail -20                   # Последние сообщения ядра
mount | grep "ro,"                 # Поиск ФС в режиме только чтения
# 3. Проверка ФС
sudo fsck -y /dev/sda1             # Проверка и исправление
# 4. Восстановление файлов
sudo fsck -r /dev/sda1             # Интерактивное восстановление
# 5. Перемонтирование в RW
sudo mount -o remount,rw /dev/sda1
# 6. Проверка диска
sudo badblocks -v /dev/sda        # Проверка на битые сектора
```
**Пояснения:**      
I/O ошибки часто указывают на проблемы с диском.      
`dmesg` показывает сообщения ядра об ошибках.      
`fsck` проверяет и исправляет ФС, но требует размонтирования.      
`badblocks` проверяет физическое состояние диска.

**Практическая работа №8: Проблемы с пользователями и аутентификацией**     

**Задание:**     
1. Невозможно войти под пользователем.     
2. Забыт пароль root.     
3. Проверьте блокировку учетной записи.     
4. Сбросьте пароль пользователя.     
5. Проверьте настройки PAM.     
6. Восстановите поврежденные файлы авторизации.     

**Решение и пояснения:**     
```bash
# 1-2. Восстановление пароля (в recovery mode)
sudo passwd username              # Смена пароля пользователя
sudo passwd root                  # Смена пароля root
# 3. Проверка блокировки
sudo passwd -S username           # Статус учетной записи
# 4. Разблокировка
sudo usermod -U username          # Разблокировка учетки
# 5. Проверка PAM
ls -la /etc/pam.d/                # Файлы конфигурации PAM
# 6. Проверка системных файлов
ls -la /etc/passwd /etc/shadow   # Права и владельцы
sudo pwck                         # Проверка целостности /etc/passwd
```
**Пояснения:**      
Recovery mode позволяет сменить пароль без знания старого.      
`passwd -S` показывает статус учетной записи (L = заблокирована).      
PAM (Pluggable Authentication Modules) управляет аутентификацией.      
`pwck` проверяет целостность файлов пользователей.

**Практическая работа №9: Проблемы с журналированием**     

**Задание:**     
1. Журналы не обновляются, занимают много места.     
2. Настройте ротацию логов.     
3. Проверьте работу службы журналирования.     
4. Очистите старые логи.     
5. Настройте уровень логирования.     
6. Восстановите поврежденные журналы.     

**Решение и пояснения:**     
```bash
# 1. Проверка размера логов
sudo du -sh /var/log/
# 2. Настройка ротации
sudo nano /etc/logrotate.conf     # Основной конфиг
# 3. Проверка службы
sudo systemctl status rsyslog     # Статус службы логирования
# 4. Очистка логов
sudo find /var/log -type f -name "*.log" -mtime +30 -delete
# 5. Настройка уровня
sudo nano /etc/rsyslog.conf       # Конфигурация rsyslog
# 6. Восстановление журналов
sudo systemctl restart rsyslog    # Перезапуск службы
```
**Пояснения:**      
`logrotate` автоматически ротирует и сжимает логи.      
`rsyslog` — основная служба журналирования.      
Очистка старых логов предотвращает переполнение диска.      
Перезапуск службы может решить проблемы с логированием.

**Практическая работа №10: Проблемы с системными службами**     

**Задание:**     
1. Служба не запускается, показывает ошибку.     
2. Проверьте статус и зависимости службы.     
3. Просмотрите логи службы.     
4. Восстановите конфигурацию службы.     
5. Переустановите службу.     
6. Настройте автозапуск службы.     

**Решение и пояснения:**
```bash
# 1-2. Проверка службы
sudo systemctl status service_name
sudo systemctl list-dependencies service_name
# 3. Просмотр логов
sudo journalctl -u service_name   # Логи конкретной службы
# 4. Восстановление конфига
sudo systemctl edit service_name  # Редактирование конфигурации
# 5. Переустановка
sudo apt install --reinstall package_name
# 6. Настройка автозапуска
sudo systemctl enable service_name
sudo systemctl start service_name
```
**Пояснения:**      
`systemctl status` показывает состояние службы и последние ошибки.      
`journalctl -u` фильтрует логи по службе.      
`systemctl edit` создает оверрайд конфигурации.      
Переустановка пакета может восстановить поврежденные файлы службы.
