**Практическая работа №1: Анализ времени загрузки системы**     

**Задание:**     
1. Определите общее время загрузки системы.     
2. Найдите службы, которые дольше всего загружаются.     
3. Проверьте, какие службы не смогли запуститься при загрузке.     
4. Просмотрите журнал загрузки текущей сессии.     
5. Определите, какие системные модули загружаются при старте.     
6. Создайте отчет о времени загрузки.     

**Решение и пояснения:**
```bash
systemd-analyze                      # 1. Общее время загрузки
systemd-analyze blame                # 2. Время инициализации каждой службы
systemctl --failed                   # 3. Неудавшиеся службы
sudo journalctl -b                   # 4. Полный журнал загрузки
lsmod                                # 5. Загруженные модули ядра
systemd-analyze time > boot_time.txt # 6. Отчет в файл
```
**Пояснения:**      
`systemd-analyze` показывает время от старта ядра до загрузки пользовательского пространства.      
`blame` сортирует службы по времени загрузки.      
`journalctl -b` показывает логи с момента последней загрузки.      
`lsmod` выводит модули ядра, загруженные в память.

**Практическая работа №2: Управление процессами загрузки**     

**Задание:**     
1. Проверьте, какие службы запускаются автоматически при загрузке.     
2. Отключите автозапуск для необязательной службы.     
3. Включите автозапуск службы.     
4. Запустите службу немедленно, не дожидаясь перезагрузки.     
5. Остановите работающую службу.     
6. Проверьте зависимости между службами.     

**Решение и пояснения:**
```bash
systemctl list-unit-files --type=service | grep enabled  # 1. Автозапускающиеся службы
sudo systemctl disable cups.service   # 2. Отключить автозапуск (пример)
sudo systemctl enable ssh.service     # 3. Включить автозапуск
sudo systemctl start ssh.service      # 4. Запустить службу сейчас
sudo systemctl stop ssh.service       # 5. Остановить службу
systemctl list-dependencies multi-user.target  # 6. Зависимости target
```
**Пояснения:**      
`disable`/`enable` управляют автозапуском при загрузке.      
`start`/`stop` управляют состоянием службы в текущей сессии.      
`list-dependencies` показывает, какие службы зависят от других.      
Изменения `enable`/`disable` сохраняются после перезагрузки.

**Практическая работа №3: Процесс выключения и перезагрузки**     

**Задание:**     
1. Выключите систему немедленно.     
2. Перезагрузите систему с задержкой 1 минута.     
3. Отмените запланированное выключение.     
4. Перезагрузите систему с сообщением для пользователей.     
5. Выполните безопасное выключение с ожиданием завершения процессов.     
6. Принудительно завершите работу без предупреждения.     

**Решение и пояснения:**     
```bash
sudo shutdown -h now                 # 1. Немедленное выключение
sudo shutdown -r +1                  # 2. Перезагрузка через 1 минуту
sudo shutdown -c                     # 3. Отмена запланированного выключения
sudo shutdown -r +5 "Сервер перезагружается"  # 4. Сообщение пользователям
sudo shutdown -h +0                  # 5. Безопасное выключение
sudo poweroff -f                     # 6. Принудительное выключение (не рекомендуется)
```
**Пояснения:**      
`shutdown` — безопасная команда для выключения.      
`-h` — halt (выключение),      
`-r` — reboot (перезагрузка).      
`+N` — через N минут.      
`now` — немедленно.      
`-c` отменяет запланированное выключение.      
`poweroff -f` принудительно завершает работу, может повредить данные.

**Практическая работа №4: Диагностика и восстановление загрузки**     

**Задание:**     
1. Загрузитесь в однопользовательском режиме (recovery).     
2. Проверьте файловую систему на ошибки.     
3. Переустановите ядро и initramfs.     
4. Восстановите загрузчик GRUB.     
5. Смонтируйте корневую файловую систему в режиме чтения-записи.     
6. Восстановите пароль root, если он утерян.     
     
**Решение и пояснения:**     
```bash
# 1. В загрузчике GRUB: добавить `single` к параметрам ядра
fsck -y /dev/sda1                    # 2. Проверка ФС (для размонтированных)
sudo apt install --reinstall linux-image-$(uname -r)  # 3. Переустановка ядра
sudo update-initramfs -u             # Обновление initramfs
sudo grub-install /dev/sda           # 4. Восстановление GRUB
sudo mount -o remount,rw /           # 5. Перемонтирование корня в RW
# 6. В recovery mode: passwd root → ввести новый пароль
```
**Пояснения:**      
Однопользовательский режим позволяет выполнять восстановление без авторизации.      
`fsck` проверяет файловую систему.      
`update-initramfs` обновляет initramfs после изменений.      
`grub-install` записывает загрузчик на диск.      
`mount -o remount,rw /` меняет режим монтирования корневой ФС.      
Восстановление пароля требует физического доступа к машине.
