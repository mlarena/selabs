**Практическая работа №1: Создание и настройка пользователей**

**Задание:**    
1. Создайте нового пользователя `testuser` с домашним каталогом.    
2. Установите для пользователя пароль.    
3. Добавьте пользователя в группу `sudo`.    
4. Измените оболочку по умолчанию для пользователя на `/bin/bash`.    
5. Заблокируйте учетную запись пользователя.    
6. Разблокируйте учетную запись и удалите пользователя.    

**Решение и пояснения:**    
```bash
sudo useradd -m testuser              # 1. Создание с домашним каталогом (-m)
sudo passwd testuser                  # 2. Установка пароля (запросит ввод)
sudo usermod -aG sudo testuser        # 3. Добавление в группу sudo
sudo chsh -s /bin/bash testuser       # 4. Изменение оболочки
sudo usermod -L testuser              # 5. Блокировка учетной записи
sudo usermod -U testuser              # 6. Разблокировка
sudo userdel -r testuser              # 6. Удаление с домашним каталогом (-r)
```
**Пояснения:**     
`useradd` создает пользователя, `-m` создает домашний каталог.     
`passwd` устанавливает/меняет пароль.     
`usermod -aG` добавляет пользователя в группу (`-a` — append, без этого пользователь будет удален из других групп).     
`-L` блокирует, `-U` разблокирует.     
`userdel -r` удаляет пользователя и его домашний каталог.

**Практическая работа №2: Работа с группами и правами доступа**

**Задание:**
1. Создайте новую группу `developers`.    
2. Добавьте двух пользователей в эту группу.    
3. Создайте каталог `/var/project` с правами 770.    
4. Настройте владельца и группу каталога.    
5. Проверьте, что пользователи группы могут создавать файлы в каталоге.    
6. Настройте SGID-бит, чтобы новые файлы наследовали группу каталога.    

**Решение и пояснения:**
```bash
sudo groupadd developers              # 1. Создание группы
sudo usermod -aG developers user1     # 2. Добавление пользователей
sudo usermod -aG developers user2
sudo mkdir /var/project               # 3. Создание каталога
sudo chmod 770 /var/project           # 3. Права rwx для владельца и группы
sudo chown root:developers /var/project  # 4. Владелец root, группа developers
sudo su - user1 -c "touch /var/project/test.txt"  # 5. Проверка (должно работать)
sudo chmod g+s /var/project           # 6. Установка SGID-бита
ls -ld /var/project                   # Проверка прав (должен быть 's' в группе)
```
**Пояснения:**     
Группы позволяют управлять правами для нескольких пользователей.     
Права 770: владелец и группа — полный доступ, остальные — нет.     
`chown user:group` меняет владельца и группу.     
SGID-бит (`g+s`) заставляет новые файлы наследовать группу каталога,     
а не первичную группу пользователя.

**Практическая работа №3: Настройка ограничений и политик**    

**Задание:**    
1. Установите срок действия пароля для пользователя (например, 90 дней).    
2. Ограничьте список доступных оболочек в `/etc/shells`.    
3. Настройте политику паролей: минимальная длина 8 символов.    
4. Запретите пользователю вход в систему (но не удаляйте учетную запись).    
5. Установите дату истечения срока действия учетной записи.    
6. Проверьте текущие настройки паролей в системе.    

**Решение и пояснения:**
```bash
sudo chage -M 90 testuser             # 1. Срок действия пароля 90 дней
sudo nano /etc/shells                 # 2. Оставить только нужные оболочки
sudo apt install libpam-pwquality     # 3. Установка модуля для политики паролей
sudo nano /etc/security/pwquality.conf  # 3. Установить: minlen = 8
sudo usermod -s /sbin/nologin testuser  # 4. Запрет входа (оболочка nologin)
sudo usermod -e 2025-01-01 testuser   # 5. Учетная запись истечет 1 января 2025
sudo chage -l testuser                # 6. Просмотр всех настроек пароля
```
**Пояснения:**     
`chage` управляет настройками срока действия пароля.     
`/etc/shells` содержит допустимые оболочки для входа.     
Модуль `pwquality` настраивает сложность паролей.     
`/sbin/nologin` запрещает вход, но оставляет учетную запись (полезно для системных пользователей).     
`-e` устанавливает дату истечения учетной записи.

**Практическая работа №4: Аудит и мониторинг пользователей**    

**Задание:**    
1. Определите, какие пользователи в данный момент вошли в систему.    
2. Проверьте историю входов пользователей.    
3. Найдите пользователей, которые никогда не меняли пароль.    
4. Определите пользователей с истекшим паролем.    
5. Проверьте членство пользователей в группах.    
6. Создайте скрипт для еженедельной проверки подозрительных активностей.    

**Решение и пояснения:**
```bash
who                                   # 1. Текущие сеансы
last -n 10                            # 2. Последние 10 входов
sudo chage -l <user> | grep "Last password change" | grep "never"  # 3. Пароль никогда не менялся
sudo grep ":*:" /etc/shadow | awk -F: '$2 == "!!" || $2 == "*" {print $1}'  # 4. Заблокированные/без пароля
groups testuser                       # 5. Группы пользователя testuser
id testuser                           # 5. Подробная информация (UID, GID, группы)

# 6. Пример скрипта audit_users.sh:
#!/bin/bash
echo "Пользователи с UID 0 (кроме root):" 
awk -F: '$3 == 0 && $1 != "root" {print $1}' /etc/passwd
echo "Пользователи без пароля:"
sudo grep ":*:" /etc/shadow | awk -F: '$2 == "" {print $1}'
```
**Пояснения:**     
`who` и `last` показывают текущие и прошлые сеансы.     
`/etc/shadow` содержит хэши паролей: `!!` или `*` означают заблокированный пароль.     
`groups` и `id` показывают членство в группах.     
Скрипт аудита помогает находить потенциальные уязвимости безопасности, например, лишние пользователи с UID 0.
