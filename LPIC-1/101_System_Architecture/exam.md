# Экзаменационные боевые задачи — Тема 101: System Architecture

Задачи максимально приближены к реальным заданиям экзамена **101-500**. Выполняйте на учебном стенде Debian.

## Задача 1. Инвентаризация оборудования

**Условие:** Определите модель CPU, объём RAM, тип диска и прерывания, используемые сетевой картой.

**Ожидаемый результат:** Команды и их вывод подтверждают характеристики системы.

**Решение и пояснения:**
```bash
lscpu                         # Модель и характеристики CPU
cat /proc/meminfo | head      # Объём памяти
lspci | grep -i net           # Сетевая карта
lsblk -d -o NAME,ROTA,SIZE    # Тип диска (ROTA=0 - SSD)
cat /proc/interrupts | grep -i eth
```
`/proc` и `/sys` — виртуальные ФС с информацией о железе. `lspci`/`lsusb` показывают устройства на шинах, `lscpu` — CPU, `/proc/interrupts` — прерывания.

## Задача 2. Настройка загрузки в однопользовательский режим

**Условие:** Сервер не загружается из-за ошибки в `/etc/fstab`. Восстановите доступ к системе.

**Ожидаемый результат:** Система загружена, ошибочная запись исправлена.

**Решение и пояснения:**
```text
1. В GRUB нажать e, добавить в строку ядра: systemd.unit=rescue.target (или single)
2. Загрузиться, смонтировать ФС в rw: mount -o remount,rw /
3. Исправить /etc/fstab
4. Перезагрузить: systemctl reboot
```
Однопользовательский/rescue режим загружает минимум служб для восстановления. Важно перемонтировать корень в rw перед правкой файлов.

## Задача 3. Смена цели загрузки и выключение

**Условие:** Переведите систему в режим без графики, затем корректно выключите её через 5 минут с уведомлением.

**Ожидаемый результат:** Цель изменена на `multi-user.target`, выключение запланировано.

**Решение и пояснения:**
```bash
sudo systemctl isolate multi-user.target
sudo systemctl set-default multi-user.target
sudo shutdown -h +5 "Плановое выключение"
sudo shutdown -c        # Отмена при необходимости
```
`systemctl isolate` меняет текущую цель, `set-default` — цель по умолчанию. `shutdown -h +5` уведомляет пользователей и выключает систему.

## Задача 4. Анализ загрузки системы

**Условие:** Определите, какие службы замедляют загрузку, и найдите ошибки при старте.

**Ожидаемый результат:** Найдены виновные службы и ошибки.

**Решение и пояснения:**
```bash
systemd-analyze
systemd-analyze blame | head
systemd-analyze critical-chain
journalctl -b -p err
```
`systemd-analyze blame` показывает время инициализации юнитов, `critical-chain` — критический путь. `journalctl -b -p err` выводит ошибки текущей загрузки.

## Задача 5. Восстановление загрузчика GRUB

**Условие:** После изменения разделов GRUB не загружается. Восстановите его из live-среды.

**Ожидаемый результат:** GRUB установлен и система загружается.

**Решение и пояснения:**
```bash
sudo mount /dev/sda2 /mnt
sudo mount --bind /dev /mnt/dev ; sudo mount --bind /proc /mnt/proc ; sudo mount --bind /sys /mnt/sys
sudo chroot /mnt
grub-install /dev/sda
update-grub
exit ; sudo reboot
```
`chroot` позволяет работать с системой как с корневой. `grub-install` ставит загрузчик в MBR/EFI, `update-grub` генерирует конфигурацию.
