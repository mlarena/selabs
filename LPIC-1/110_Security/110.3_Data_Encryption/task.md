**Практическая работа №1: Ключи SSH**

**Задание:**
1. Сгенерируйте пару ключей Ed25519.
2. Посмотрите созданные файлы в `~/.ssh`.
3. Скопируйте публичный ключ на удалённый сервер.
4. Войдите на сервер без пароля.
5. Объясните назначение открытого и закрытого ключа.

**Решение и пояснения:**
```bash
ssh-keygen -t ed25519 -C "student@lab"   # 1. Генерация ключей
ls -l ~/.ssh/                            # 2. id_ed25519, id_ed25519.pub
ssh-copy-id user@server                  # 3. Копирование публичного ключа
ssh user@server                          # 4. Вход без пароля
```
**Пояснения:**
Открытый ключ (`id_ed25519.pub`) помещается в `~/.ssh/authorized_keys` на сервере, закрытый (`id_ed25519`) остаётся у пользователя и никому не передаётся. Аутентификация по ключу безопаснее пароля и удобна для автоматизации.

**Практическая работа №2: Ключи хоста SSH**

**Задание:**
1. Посмотрите ключи хоста сервера.
2. Определите отпечатки ключей.
3. Проверьте запись сервера в `known_hosts`.
4. Удалите старую запись сервера.
5. Объясните, зачем нужны ключи хоста.

**Решение и пояснения:**
```bash
ls -l /etc/ssh/ssh_host_*_key.pub        # 1. Публичные ключи хоста
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub   # 2. Отпечаток
cat ~/.ssh/known_hosts                   # 3. Записи серверов
ssh-keygen -R server                     # 4. Удаление записи
```
**Пояснения:**
Ключи хоста идентифицируют сервер при подключении, защищая от MITM. Клиент сохраняет отпечатки в `~/.ssh/known_hosts`. Если ключ сервера изменился, SSH предупреждает о возможной атаке.

**Практическая работа №3: GnuPG — шифрование и подпись**

**Задание:**
1. Сгенерируйте пару ключей GPG.
2. Посмотрите список ключей.
3. Зашифруйте файл для получателя.
4. Расшифруйте файл.
5. Подпишите файл и проверьте подпись.

**Решение и пояснения:**
```bash
gpg --full-generate-key                   # 1. Генерация ключа
gpg --list-keys                           # 2. Список ключей
gpg --encrypt --recipient user@example.com file.txt   # 3. Шифрование
gpg --decrypt file.txt.gpg > file.out     # 4. Расшифровка
gpg --sign file.txt                       # 5. Подпись
gpg --verify file.txt.gpg                 # 5. Проверка подписи
```
**Пояснения:**
GPG использует асимметричную криптографию: шифрование — открытым ключом получателя, расшифровка — его закрытым ключом. Подпись создаётся закрытым ключом отправителя и проверяется открытым. Ключи хранятся в `~/.gnupg/`.

**Практическая работа №4: SSH-туннели**

**Задание:**
1. Создайте локальный туннель на порт 8080.
2. Проверьте туннель через браузер/curl.
3. Создайте динамический SOCKS-туннель.
4. Настройте X11-форвардинг.
5. Объясните разницу между локальным, удалённым и динамическим туннелем.

**Решение и пояснения:**
```bash
ssh -L 8080:localhost:80 user@server     # 1. Локальный туннель
curl http://localhost:8080               # 2. Проверка
ssh -D 1080 user@server                  # 3. SOCKS-прокси
ssh -X user@server xeyes                 # 4. X11-форвардинг
```
**Пояснения:**
`-L` — локальный туннель (локальный порт → удалённый сервис), `-R` — удалённый, `-D` — динамический SOCKS-прокси, `-X` — форвардинг X11. Туннели шифруют трафик и позволяют обходить ограничения, но требуют доверия к серверу.
