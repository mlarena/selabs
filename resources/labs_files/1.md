Вопрос № 1: Какая из поддерживаемых в Astra Linux Special Edition файловая система позволяет создавать снимки состояния?
Отличный вопрос! Это действительно ключевая тема для понимания современных возможностей Linux.

В Debian поддерживается несколько файловых систем, которые позволяют создавать снимки состояния (снапшоты). Основные из них:

## 1. **Btrfs (B-Tree File System)** — **Главный и самый популярный вариант** 

Btrfs — это современная копируемая-при-записи (Copy-on-Write, CoW) файловая система, в которую функциональность снимков встроена на уровне дизайна.

**Как это работает:**
- Снимки в Btrfs создаются практически мгновенно, независимо от размера данных
- Первоначально снимок не занимает дополнительного места на диске
- При изменении оригинальных файлов Btrfs сохраняет как старые, так и новые версии данных 
- Поддерживаются как read-only, так и read-write снимки 

**Ключевые особенности:**
- Нативная поддержка снапшотов через команду `btrfs subvolume snapshot`
- Возможность отката системы к предыдущему состоянию
- Интеграция с загрузчиком GRUB для загрузки со снимков 
- Поддержка автоматических снимков через инструмент `snapper` 

## 2. **ZFS** — **Альтернатива с мощными возможностями** 

ZFS также поддерживается в Debian (пакет `zfsutils-linux`) и предоставляет схожую функциональность:

- Снимки создаются через `zfs snapshot`
- Доступ к файлам из снимков через специальный каталог `.zfs/snapshot` 
- Поддержка промоушена снимков (превращения снимка в активное состояние) 

## 3. **XFS** — **Ограниченная поддержка через reflink** 

XFS тоже поддерживает копирование-при-записи (reflink), но подход отличается:

- Снимки создаются не как отдельная сущность, а через копирование с опцией `--reflink`
- Команда: `cp --reflink --archive` создаёт копию, которая изначально не занимает места
- Менее удобна для системных снимков, но подходит для файловых "моментальных снимков" 

## 4. **LVM (не файловая система, но важно упомянуть)** 

Хотя это не файловая система, а менеджер томов, LVM предоставляет снимки на уровне блочных устройств:

- Поддерживает тонкие тома (thin-provisioning) для эффективных снимков
- Может работать с любой файловой системой поверх LVM
- Управляется через `lvcreate --snapshot`

# Лабораторная работа: "Знакомство со снимками Btrfs"

## Цель работы
На практике изучить создание и управление снимками файловой системы Btrfs в Debian.

## Подготовка

### Шаг 1: Создание виртуального диска
Для безопасного эксперимента создадим образ диска и подключим его как loop-устройство:

```bash
# Создаём файл-образ размером 1 ГБ
dd if=/dev/zero of=~/btrfs_test.img bs=1M count=1024

# Подключаем как loop-устройство
sudo losetup -fP ~/btrfs_test.img

# Узнаем, какое устройство создалось
losetup -l | grep btrfs_test
# Предположим, это /dev/loop0
```

### Шаг 2: Создание файловой системы Btrfs
```bash
# Создаём Btrfs на нашем виртуальном диске
sudo mkfs.btrfs /dev/loop0

# Создаём точку монтирования
mkdir -p ~/btrfs_mount

# Монтируем
sudo mount /dev/loop0 ~/btrfs_mount

# Проверяем владельца и права
sudo chown $USER:$USER ~/btrfs_mount
```

## Основная часть

### Шаг 3: Подготовка тестовых данных
```bash
# Создаём тестовые файлы и каталоги
cd ~/btrfs_mount
mkdir documents projects
echo "Это важный документ версия 1" > documents/important.txt
echo "Код проекта версия 1" > projects/main.c
echo "Конфигурация" > config.ini

# Смотрим текущую структуру
ls -la
tree
```

### Шаг 4: Создание первого снимка
```bash
# Создаём каталог для снимков
sudo mkdir -p ~/btrfs_mount/.snapshots

# Создаём снимок текущего состояния
sudo btrfs subvolume snapshot ~/btrfs_mount ~/btrfs_mount/.snapshots/initial_state

# Проверяем созданный снимок
btrfs subvolume list ~/btrfs_mount
```

### Шаг 5: Модификация данных и создание второго снимка
```bash
# Изменяем файлы (имитируем работу)
echo "Это важный документ версия 2 (обновлено)" > documents/important.txt
echo "Новый файл с данными" > data.csv
rm projects/main.c

# Проверяем изменения
ls -la
cat documents/important.txt

# Создаём второй снимок - состояние после изменений
sudo btrfs subvolume snapshot ~/btrfs_mount ~/btrfs_mount/.snapshots/after_changes

# Смотрим оба снимка
ls -la .snapshots/
btrfs subvolume list ~/btrfs_mount
```

### Шаг 6: Сравнение снимков и восстановление
```bash
# Сравниваем содержимое снимков
diff -r .snapshots/initial_state/ .snapshots/after_changes/

# Восстанавливаем удалённый файл из первого снимка
cp .snapshots/initial_state/projects/main.c projects/

# Полный откат системы к состоянию первого снимка
# (ВАЖНО: удаляем текущее содержимое и копируем из снимка)
rm -rf ~/btrfs_mount/documents ~/btrfs_mount/projects ~/btrfs_mount/*.ini ~/btrfs_mount/*.csv
cp -a .snapshots/initial_state/* ~/btrfs_mount/

# Проверяем результат восстановления
ls -la
cat documents/important.txt  # Должна быть "версия 1"
```

### Шаг 7: Read-only снимки и снаппер
```bash
# Создаём read-only снимок (защита от изменений)
sudo btrfs subvolume snapshot -r ~/btrfs_mount ~/btrfs_mount/.snapshots/readonly_backup

# Пытаемся изменить read-only снимок (должно не получиться)
touch .snapshots/readonly_backup/test_file  # Ошибка!

# Установка snapper для автоматического управления снимками (опционально)
sudo apt update
sudo apt install snapper

# Создание конфигурации snapper для нашего раздела
sudo snapper -c test_config create-config ~/btrfs_mount

# Просмотр настроек
sudo snapper -c test_config get-config

# Ручное создание снимка через snapper
sudo snapper -c test_config create -d "Мой первый снаппер-снимок"

# Просмотр списка снимков через snapper
sudo snapper -c test_config list
```

### Шаг 8: Очистка
```bash
# Возвращаемся в домашнюю директорию
cd ~

# Размонтируем
sudo umount ~/btrfs_mount

# Отключаем loop-устройство
sudo losetup -d /dev/loop0

# Удаляем тестовые файлы (опционально)
rm ~/btrfs_test.img
rm -rf ~/btrfs_mount
```

3. Убедились, что снимки создаются мгновенно и фиксируют состояние файлов
4. Продемонстрировали возможность восстановления отдельных файлов и полного отката системы
5. Познакомились с read-only снимками и инструментом `snapper`

## Ответ на вопрос

**Основная файловая система в Debian для создания снимков состояния — Btrfs.** 

Она предоставляет наиболее полную, нативную и удобную поддержку снапшотов. Также возможны варианты с ZFS, XFS (через reflink) и LVM (на уровне блочных устройств), но Btrfs является стандартом де-факто для этой задачи в экосистеме Linux .
