# Экзаменационные боевые задачи — Тема 109: Networking Fundamentals

Задачи приближены к реальным заданиям экзамена **102-500**.

## Задача 1. Основы IP-протоколов

**Условие:** Определите адрес, маску, шлюз и диапазон подсети для интерфейса `192.168.10.50/26`.

**Ожидаемый результат:** Рассчитаны параметры подсети.

**Решение и пояснения:**
```bash
ipcalc 192.168.10.50/26
ip -br addr show
ip route show
# Диапазон: 192.168.10.0 - 192.168.10.63, хостов: 62, broadcast: 192.168.10.63
```
`/26` = 255.255.255.192, 64 адреса, 62 хоста. `ipcalc` помогает считать подсети. IPv4-адрес + маска определяют сеть, broadcast и диапазон хостов.

## Задача 2. Постоянная конфигурация сети

**Условие:** Настройте статический IP на `eth0` через NetworkManager и сделайте его постоянным.

**Ожидаемый результат:** Интерфейс имеет статический адрес.

**Решение и пояснения:**
```bash
nmcli con add type ethernet ifname eth0 con-name static1 \
  ip4 192.168.10.50/26 gw4 192.168.10.1
nmcli con mod static1 ipv4.dns "192.168.10.1 8.8.8.8"
nmcli con up static1
nmcli con show static1
```
NetworkManager хранит подключения в `/etc/NetworkManager/system-connections/`. `nmcli con add/mod` создаёт и меняет настройки, `up` активирует. Альтернатива — `/etc/network/interfaces` (ifupdown).

## Задача 3. Диагностика сети

**Условие:** Проверьте связность, найдите обрыв маршрута и проверьте открытые порты.

**Ожидаемый результат:** Проблема локализована.

**Решение и пояснения:**
```bash
ping -c2 127.0.0.1        # Стек
ping -c2 <gateway>        # Локальная сеть
ping -c2 8.8.8.8          # Маршрут/интернет
traceroute 8.8.8.8        # Где обрыв
ss -tlnp                  # Слушающие порты
ip neigh                  # ARP-таблица
```
Диагностика идёт по уровням: loopback → шлюз → внешний узел → DNS. `traceroute` показывает путь, `ss` — сокеты, `ip neigh` — соседей.

## Задача 4. Клиентский DNS

**Условие:** Настройте DNS-серверы и порядок разрешения имён, проверьте разрешение.

**Ожидаемый результат:** DNS настроен и работает.

**Решение и пояснения:**
```bash
# /etc/resolv.conf: nameserver 192.168.10.1 ; nameserver 8.8.8.8
# /etc/nsswitch.conf: hosts: files dns
getent hosts example.com
dig example.com @8.8.8.8
cat /etc/hosts
```
`/etc/resolv.conf` задаёт DNS-серверы, `/etc/nsswitch.conf` — порядок источников (файлы → DNS). `getent` использует NSS. Локальные записи — в `/etc/hosts`.

## Задача 5. Проверка доступности службы

**Условие:** Проверьте, отвечает ли веб-сервер на порту 80 и корректны ли заголовки.

**Ожидаемый результат:** Служба проверена.

**Решение и пояснения:**
```bash
nc -zv server 80
curl -I http://server
curl -v http://server 2>&1 | head
ss -tlnp | grep :80
```
`nc -z` проверяет порт, `curl -I` — заголовки ответа, `-v` — подробный обмен. `ss` показывает, слушает ли кто-то порт локально.
