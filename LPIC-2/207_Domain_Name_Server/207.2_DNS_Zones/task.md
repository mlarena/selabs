**Практическая работа №1: Прямая зона с разными записями**

**Задание:**
1. Создайте зону `example.lab`.
2. Добавьте записи A, AAAA, MX, TXT.
3. Добавьте несколько A для одного имени (round-robin).
4. Проверьте зону.
5. Запросите каждую запись.

**Решение и пояснения:**
```bash
# db.example.lab:
# @   IN SOA ns.example.lab. admin.example.lab. (2024010101 3600 1800 604800 86400)
# @   IN NS  ns.example.lab.
# @   IN MX  10 mail.example.lab.
# @   IN TXT "v=spf1 mx -all"
# ns  IN A   192.168.1.10
# www IN A   192.168.1.20
# www IN A   192.168.1.21
# mail IN A  192.168.1.30
sudo named-checkzone example.lab /etc/bind/db.example.lab
dig @localhost MX example.lab +short
dig @localhost TXT example.lab +short
```
**Пояснения:**
Разные типы записей описывают разные сервисы: A/AAAA — адреса, MX — почта, TXT — произвольные данные (SPF, верификация). Несколько A для одного имени дают простую балансировку (round-robin).

**Практическая работа №2: Делегирование подзоны**

**Задание:**
1. Создайте родительскую зону `lab`.
2. Создайте дочернюю зону `dev.lab`.
3. Делегируйте `dev.lab` через NS-записи.
4. Проверьте делегирование.
5. Объясните назначение делегирования.

**Решение и пояснения:**
```bash
# В зоне lab:
# dev IN NS ns.dev.lab.
# ns.dev IN A 192.168.1.40
# Зона dev.lab на своём сервере:
# @ IN SOA ns.dev.lab. admin.dev.lab. (1 3600 1800 604800 86400)
# @ IN NS  ns.dev.lab.
# ns IN A   192.168.1.40
dig @localhost www.dev.lab
```
**Пояснения:**
Делегирование передаёт управление подзоной другому серверу через NS-записи и «glue»-записи A для сервера подзоны. Это позволяет распределять администрирование DNS между организациями.

**Практическая работа №3: Проверка и отладка зон**

**Задание:**
1. Проверьте зону на синтаксис.
2. Скомпилируйте зону в бинарный формат.
3. Найдите ошибки в зоне.
4. Посмотрите журнал BIND.
5. Исправьте найденную ошибку.

**Решение и пояснения:**
```bash
sudo named-checkzone example.lab /etc/bind/db.example.lab
sudo named-compilezone -f text -F text -o /tmp/zone.out example.lab /etc/bind/db.example.lab
sudo journalctl -u bind9 | tail -30        # 4. Журнал
sudo rndc reload                           # Применение после исправления
```
**Пояснения:**
`named-checkzone` проверяет корректность зоны, `named-compilezone` компилирует её. Ошибки (пропущенная точка, неверный SOA) видны в выводе и журнале BIND. Типичная ошибка — отсутствие завершающей точки в FQDN.

**Практическая работа №4: Инструменты запросов**

**Задание:**
1. Запросите запись через `dig` с трассировкой.
2. Используйте `nslookup` в интерактивном режиме.
3. Запросите запись через `host`.
4. Проверьте зону через AXFR (если разрешено).
5. Объясните различия инструментов.

**Решение и пояснения:**
```bash
dig +trace example.lab                 # 1. Трассировка разрешения
nslookup                             # 2. Интерактивный режим
host -t MX example.lab               # 3. Быстрый запрос
dig AXFR example.lab @localhost      # 4. Передача зоны
```
**Пояснения:**
`dig +trace` показывает весь путь разрешения от корня. `nslookup` — интерактивный клиент. `host` — краткий вывод. `AXFR` — полная передача зоны (обычно ограничена). Инструменты взаимозаменяемы, `dig` — самый информативный.
