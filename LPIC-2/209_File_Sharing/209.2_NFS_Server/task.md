**Практическая работа №1: Настройка NFS-сервера**

**Задание:**
1. Установите NFS-сервер.
2. Создайте экспортируемый каталог.
3. Опишите экспорт в `/etc/exports`.
4. Примените экспорт.
5. Проверьте список экспортов.

**Решение и пояснения:**
```bash
sudo apt install -y nfs-kernel-server
sudo mkdir -p /srv/nfs/data
sudo tee -a /etc/exports >/dev/null <<'EOF'
/srv/nfs/data 192.168.1.0/24(rw,sync,no_subtree_check)
EOF
sudo exportfs -ra                       # 4. Применить
sudo exportfs -v                        # 5. Список экспортов
```
**Пояснения:**
NFS экспортирует каталоги по сети. `/etc/exports` задаёт каталог, разрешённые хосты и опции. `exportfs -ra` применяет конфигурацию без перезапуска. `sync` обеспечивает согласованность записи.

**Практическая работа №2: Монтирование NFS на клиенте**

**Задание:**
1. Установите NFS-клиент.
2. Смонтируйте экспорт вручную.
3. Настройте автомонтирование в fstab.
4. Проверьте права доступа.
5. Размонтируйте ресурс.

**Решение и пояснения:**
```bash
sudo apt install -y nfs-common
sudo mkdir -p /mnt/nfs
sudo mount -t nfs server:/srv/nfs/data /mnt/nfs          # 2. Монтирование
# fstab: server:/srv/nfs/data /mnt/nfs nfs defaults 0 0
mount | grep nfs
sudo umount /mnt/nfs
```
**Пояснения:**
`mount -t nfs` подключает экспорт. Для автомонтирования добавляют запись в `/etc/fstab`. Опции монтирования (`soft`/`hard`, `rw`) влияют на поведение при недоступности сервера. NFS использует UID/GID для прав.

**Практическая работа №3: Ограничение доступа и безопасность NFS**

**Задание:**
1. Ограничьте экспорт конкретной подсетью.
2. Добавьте опцию `root_squash`.
3. Проверьте, что root клиента не имеет прав root на сервере.
4. Ограничьте доступ через firewall.
5. Объясните риски NFS.

**Решение и пояснения:**
```bash
# /etc/exports:
# /srv/nfs/data 192.168.1.0/24(rw,sync,root_squash,no_all_squash)
sudo exportfs -ra
# Firewall: разрешить NFS-порты только из подсети
sudo iptables -A INPUT -s 192.168.1.0/24 -p tcp --dport 2049 -j ACCEPT
```
**Пояснения:**
`root_squash` (по умолчанию) сопоставляет root клиента пользователю `nobody`, предотвращая доступ к root-файлам. NFS передаёт данные без шифрования, поэтому ограничивают доступ по подсети и firewall.

**Практическая работа №4: Диагностика NFS**

**Задание:**
1. Посмотрите экспорты сервера с клиента.
2. Проверьте RPC-службы.
3. Посмотрите статистику NFS.
4. Найдите причины недоступности.
5. Объясните роль rpcbind.

**Решение и пояснения:**
```bash
showmount -e server                     # 1. Экспорты сервера
rpcinfo -p server                       # 2. RPC-службы
nfsstat -c                              # 3. Статистика клиента
sudo systemctl status rpcbind nfs-server
journalctl -u nfs-server | tail
```
**Пояснения:**
`showmount -e` показывает доступные экспорты. `rpcinfo -p` — зарегистрированные RPC-программы. `rpcbind` (portmapper) сопоставляет RPC-программы портам. Типовые проблемы: firewall, отсутствие экспорта, недоступность rpcbind.
