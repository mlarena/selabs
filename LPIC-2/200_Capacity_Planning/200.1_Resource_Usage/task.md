**Практическая работа №1: Измерение загрузки CPU**

**Задание:**
1. Посмотрите среднюю загрузку системы за 1/5/15 минут.
2. Выведите снимок статистики CPU, памяти и процессов.
3. Запустите нагрузку и пронаблюдайте за `us`/`sy`/`id`.
4. Определите количество ядер и их загрузку.
5. Объясните, что означает load average.

**Решение и пояснения:**
```bash
uptime                       # 1. load average: 1/5/15 минут
vmstat 1 5                   # 2. Статистика каждую секунду, 5 раз
# Запуск нагрузки:
yes > /dev/null & yes > /dev/null &
mpstat -P ALL 1 3            # 4. Загрузка по ядрам (пакет sysstat)
```
**Пояснения:**
Load average — среднее число процессов в очереди на выполнение и в непрерываемом ожидании I/O. Сравнивайте его с числом ядер (`nproc`). `vmstat` показывает `us` (user), `sy` (system), `id` (idle), `wa` (iowait). `mpstat` даёт разбивку по ядрам.

**Практическая работа №2: Измерение использования памяти**

**Задание:**
1. Посмотрите общее использование памяти.
2. Определите, сколько памяти в кэше.
3. Пронаблюдайте изменение памяти во времени.
4. Найдите топ-5 процессов по памяти.
5. Объясните поля `buff/cache` и `available`.

**Решение и пояснения:**
```bash
free -h                                  # 1-2. Память и кэш
vmstat 1 5                               # 3. Динамика (колонки si/so, free)
ps aux --sort=-%mem | head -6            # 4. Топ по памяти
```
**Пояснения:**
`buff/cache` — память под кэш файлов и буферы (может быть освобождена). `available` — оценка доступной памяти для новых процессов без свопа. Высокий `si`/`so` в vmstat указывает на активное использование swap — признак нехватки RAM.

**Практическая работа №3: Измерение дискового ввода-вывода**

**Задание:**
1. Посмотрите расширенную статистику дисков.
2. Пронаблюдайте загрузку диска в реальном времени.
3. Найдите процессы с наибольшим I/O.
4. Определите загруженный диск и его утилизацию.
5. Объясните показатель %util.

**Решение и пояснения:**
```bash
iostat -x 1 5                    # 1-2. Расширенная статистика (sysstat)
sudo iotop -o                    # 3. Процессы с активным I/O
pidstat -d 1 5                   # 3. I/O по процессам
```
**Пояснения:**
`iostat -x` показывает `%util` — долю времени, когда устройство было занято обработкой запросов (близко к 100% = узкое место). `await` — среднее время ожидания. `iotop` показывает процессы, активно читающие/пишущие на диск.

**Практическая работа №4: Измерение сетевого трафика и пропускной способности**

**Задание:**
1. Посмотрите активные соединения и слушающие порты.
2. Пронаблюдайте сетевую статистику интерфейсов.
3. Соберите статистику трафика по процессам.
4. Определите топ-источники трафика.
5. Объясните, как выявить узкое место сети.

**Решение и пояснения:**
```bash
ss -s                            # 1. Сводка по сокетам
sar -n DEV 1 5                   # 2. Трафик по интерфейсам (sysstat)
sudo nethogs eth0                # 3. Трафик по процессам
sudo iftop -i eth0               # 3. Трафик по соединениям
```
**Пояснения:**
`sar -n DEV` показывает пакеты/байты в секунду по интерфейсам. `nethogs` и `iftop` в реальном времени связывают трафик с процессами и соединениями. Рост `rx/tx` при насыщении канала и потерях указывает на узкое место сети.
