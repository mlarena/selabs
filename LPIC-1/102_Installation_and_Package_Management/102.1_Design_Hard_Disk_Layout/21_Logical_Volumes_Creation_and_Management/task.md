**Практическая работа №1: Создание LVM и базовых томов**     

**Задание:**     
1. Создайте физический том (PV) на разделе `/dev/sdb1`.     
2. Создайте группу томов (VG) с именем `vg_data`.     
3. Добавьте физический том в группу томов.     
4. Создайте логический том (LV) размером 2GB с именем `lv_home`.     
5. Отформатируйте логический том в файловую систему ext4.     
6. Смонтируйте том и проверьте его доступность.     

**Решение и пояснения:**
```bash
sudo pvcreate /dev/sdb1              # 1. Создание физического тома
sudo vgcreate vg_data /dev/sdb1      # 2,3. Создание VG и добавление PV
sudo lvcreate -L 2G -n lv_home vg_data  # 4. Создание LV размером 2GB
sudo mkfs.ext4 /dev/vg_data/lv_home  # 5. Форматирование
sudo mount /dev/vg_data/lv_home /mnt # 6. Монтирование
df -h /mnt                           # Проверка размера и доступности
```
**Пояснения:**      
LVM состоит из трех уровней:      
PV (физический том),      
VG (группа томов),      
LV (логический том).      
`pvcreate` инициализирует раздел как PV.      
`vgcreate` создает VG и добавляет в него PV.      
`lvcreate` создает LV внутри VG.      
Путь к LV: `/dev/<vg_name>/<lv_name>`.

**Практическая работа №2: Расширение логического тома**     

**Задание:**     
1. Добавьте новый физический том (`/dev/sdc1`) в группу томов `vg_data`.     
2. Увеличьте размер логического тома `lv_home` на 1GB.     
3. Расширьте файловую систему на логическом томе.     
4. Проверьте новый размер тома.     
5. Создайте снапшот (snapshot) логического тома.     
6. Убедитесь, что снапшот создан.     

**Решение и пояснения:**     
```bash
sudo pvcreate /dev/sdc1              # Создание нового PV
sudo vgextend vg_data /dev/sdc1      # 1. Расширение VG новым PV
sudo lvextend -L +1G /dev/vg_data/lv_home  # 2. Увеличение LV на 1GB
sudo resize2fs /dev/vg_data/lv_home  # 3. Расширение ФС (для ext4)
df -h /mnt                           # 4. Проверка нового размера
sudo lvcreate -s -L 500M -n lv_home_snap /dev/vg_data/lv_home  # 5. Создание снапшота
sudo lvs                              # 6. Просмотр всех LV, включая снапшоты
```
**Пояснения:**      
`vgextend` добавляет PV в существующую VG.      
`lvextend` увеличивает размер LV.      
`resize2fs` расширяет файловую систему ext4 на увеличенном LV (для xfs используйте `xfs_growfs`).      
Снапшот (-s) — копия тома на определенный момент времени, полезно для бэкапов.

**Практическая работа №3: Уменьшение и перемещение томов**     

**Задание:**     
1. Уменьшите файловую систему на логическом томе (на 500MB).     
2. Уменьшите размер логического тома.     
3. Переместите данные с одного физического тома на другой.     
4. Удалите физический том из группы томов.     
5. Переименуйте группу томов.     
6. Проверьте целостность конфигурации LVM.     

**Решение и пояснения:**
```bash
# Внимание: Уменьшение требует размонтирования и проверки ФС!
sudo umount /mnt
sudo e2fsck -f /dev/vg_data/lv_home  # Проверка ФС
sudo resize2fs /dev/vg_data/lv_home 1.5G  # 1. Уменьшение ФС до 1.5GB
sudo lvreduce -L 1.5G /dev/vg_data/lv_home  # 2. Уменьшение LV
sudo mount /dev/vg_data/lv_home /mnt  # Монтирование обратно
sudo pvmove /dev/sdb1 /dev/sdc1      # 3. Перемещение данных между PV
sudo vgreduce vg_data /dev/sdb1      # 4. Удаление PV из VG
sudo vgrename vg_data vg_storage     # 5. Переименование VG
sudo vgdisplay                       # 6. Проверка конфигурации
```
**Пояснения:**      
Уменьшение требует осторожности:      
сначала уменьшаем ФС, затем LV.      
`pvmove` перемещает данные с одного PV на другой, что полезно при замене дисков.      
`vgreduce` удаляет пустой PV из VG.      
Переименование VG обновляет все ссылки автоматически.

**Практическая работа №4: Восстановление и удаление LVM**     

**Задание:**     
1. Удалите логический том.     
2. Удалите группу томов.     
3. Удалите метки LVM с физических томов.     
4. Восстановите группу томов из резервной конфигурации.     
5. Активируйте и деактивируйте группу томов.     
6. Создайте резервную копию конфигурации LVM.     

**Решение и пояснения:**     
```bash
sudo umount /dev/vg_storage/lv_home  # Размонтирование
sudo lvremove /dev/vg_storage/lv_home  # 1. Удаление LV (подтвердить)
sudo vgremove vg_storage             # 2. Удаление VG
sudo pvremove /dev/sdb1 /dev/sdc1    # 3. Удаление PV (стирает метки LVM)
# 4. Восстановление (если есть backup):
sudo vgcfgrestore -f /etc/lvm/backup/vg_data vg_data
sudo vgchange -ay vg_data            # 5. Активация VG
sudo vgchange -an vg_data            # 5. Деактивация VG
sudo vgcfgbackup vg_data             # 6. Резервное копирование конфигурации
```
**Пояснения:**      
`lvremove`, `vgremove`, `pvremove` удаляют соответствующие компоненты LVM.      
`vgcfgbackup` создает резервную копию метаданных VG в `/etc/lvm/backup/`.      
`vgcfgrestore` восстанавливает из резервной копии.      
`vgchange -ay` активирует VG (автоматически при загрузке),      
`-an` деактивирует.      
Резервные копии важны для восстановления.
