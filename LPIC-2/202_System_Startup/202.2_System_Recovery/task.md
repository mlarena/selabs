**Практическая работа №1: Восстановление через GRUB**

**Задание:**
1. Откройте меню GRUB при загрузке.
2. Войдите в командную строку GRUB.
3. Найдите ядро на диске вручную.
4. Загрузите систему в однопользовательском режиме.
5. Объясните назначение режима восстановления.

**Решение и пояснения:**
```text
# В меню GRUB нажмите 'e' для редактирования, 'c' для командной строки
# В командной строке GRUB:
ls                    # список устройств
ls (hd0,gpt2)/        # просмотр разделов
set root=(hd0,gpt2)
linux /boot/vmlinuz-<ver> root=/dev/sda2 ro single
initrd /boot/initrd.img-<ver>
boot
```
**Пояснения:**
Командная строка GRUB позволяет вручную найти ядро и загрузиться при повреждённой конфигурации. Параметр `single` (или `systemd.unit=rescue.target`) загружает однопользовательский режим для восстановления.

**Практическая работа №2: Режимы rescue и emergency**

**Задание:**
1. Загрузитесь в `rescue.target`.
2. Размонтируйте и проверьте корневую ФС.
3. Загрузитесь в `emergency.target`.
4. Смонтируйте корень в режиме только чтение.
5. Объясните разницу между rescue и emergency.

**Решение и пояснения:**
```bash
systemctl rescue          # 1. Режим rescue
systemctl emergency       # 3. Режим emergency
# Параметры ядра: systemd.unit=rescue.target / emergency.target
mount -o remount,rw /     # Смонтировать корень на запись
fsck -y /dev/sda2         # Проверка ФС (когда не смонтирована)
```
**Пояснения:**
`rescue.target` монтирует локальные ФС и запускает минимум служб. `emergency.target` запускает только оболочку, корень смонтирован только для чтения. Emergency используется при серьёзных повреждениях.

**Практическая работа №3: Восстановление загрузчика**

**Задание:**
1. Посмотрите установленные загрузчики.
2. Переустановите GRUB на диск (BIOS).
3. Переустановите GRUB для UEFI.
4. Проверьте записи загрузки UEFI.
5. Объясните различия установки BIOS и UEFI.

**Решение и пояснения:**
```bash
sudo grub-install /dev/sda                 # 2. BIOS/MBR
sudo grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=debian  # 3. UEFI
sudo update-grub                           # Обновление конфигурации
efibootmgr -v                              # 4. Записи UEFI
```
**Пояснения:**
При BIOS GRUB ставится в MBR диска (`/dev/sda`). При UEFI — в EFI System Partition, а запись создаётся через `efibootmgr`. Для восстановления загрузки с live-USB монтируют систему и выполняют `grub-install`/`update-grub` в `chroot`.

**Практическая работа №4: Восстановление после сбоя**

**Задание:**
1. Смоделируйте повреждение `/etc/fstab`.
2. Загрузитесь в emergency-режиме.
3. Смонтируйте корень на запись.
4. Исправьте `fstab`.
5. Перезагрузитесь и проверьте.

**Решение и пояснения:**
```bash
# Ошибка в fstab -> система уходит в emergency
mount -o remount,rw /              # 3. Корень на запись
nano /etc/fstab                    # 4. Исправление
findmnt --verify                   # Проверка синтаксиса
reboot                             # 5. Перезагрузка
```
**Пояснения:**
Неверная запись в `/etc/fstab` блокирует загрузку. Решение: войти в emergency/rescue, перемонтировать корень на запись, исправить файл, проверить через `findmnt --verify`, перезагрузиться. UUID можно уточнить командой `blkid`.
