**Практическая работа №1: Усиление sshd_config**

**Задание:**
1. Запретите вход root по SSH.
2. Отключите вход по паролю.
3. Разрешите вход только определённым пользователям.
4. Ограничьте количество попыток.
5. Перезапустите SSH и проверьте.

**Решение и пояснения:**
```bash
# /etc/ssh/sshd_config:
# PermitRootLogin no
# PasswordAuthentication no
# PubKeyAuthentication yes
# AllowUsers user1 user2
# MaxAuthTries 3
sudo sshd -t                              # Проверка конфигурации
sudo systemctl restart ssh
```
**Пояснения:**
`PermitRootLogin no` запрещает прямой root-вход, `PasswordAuthentication no` оставляет только ключи, `AllowUsers` ограничивает список пользователей. `sshd -t` проверяет конфигурацию до перезапуска, чтобы не потерять доступ.

**Практическая работа №2: Множественные соединения и защита от потери доступа**

**Задание:**
1. Откройте несколько SSH-сессий.
2. Используйте `screen`/`tmux` для устойчивости.
3. Настройте `ControlMaster` для переиспользования соединения.
4. Протестируйте изменения без потери доступа.
5. Объясните практику безопасного изменения SSH.

**Решение и пояснения:**
```bash
ssh user@server                          # сессия 1
ssh user@server                          # сессия 2 (резерв)
tmux new -s work                         # устойчивая сессия
# ~/.ssh/config:
# Host server
#   ControlMaster auto
#   ControlPath ~/.ssh/cm-%r@%h:%p
#   ControlPersist 10m
```
**Пояснения:**
При изменении SSH всегда держат запасную сессию, чтобы не потерять доступ при ошибке. `ControlMaster` переиспользует соединение (ускоряет повторные подключения). `tmux`/`screen` сохраняют сессию при обрыве связи.

**Практическая работа №3: SSH-туннели и форвардинг**

**Задание:**
1. Настройте локальный форвардинг порта.
2. Настройте удалённый форвардинг.
3. Настройте динамический SOCKS-прокси.
4. Проверьте туннель.
5. Объясните сценарии применения.

**Решение и пояснения:**
```bash
ssh -L 3306:db.internal:3306 user@jump    # 1. Локальный форвард
ssh -R 8080:localhost:80 user@remote      # 2. Удалённый форвард
ssh -D 1080 user@server                   # 3. SOCKS-прокси
curl --socks5 localhost:1080 http://example.com   # 4. Проверка
```
**Пояснения:**
`-L` пробрасывает локальный порт к удалённому сервису, `-R` — удалённый порт к локальному сервису, `-D` — динамический SOCKS-прокси. Туннели шифруют трафик и позволяют безопасно обходить сетевые ограничения.

**Практическая работа №4: Диагностика SSH**

**Задание:**
1. Посмотрите журнал SSH-подключений.
2. Включите подробный режим клиента.
3. Найдите неудачные попытки входа.
4. Проверьте права на ключи и каталоги.
5. Объясните типовые проблемы.

**Решение и пояснения:**
```bash
sudo journalctl -u ssh | tail
ssh -vvv user@server                     # 2. Подробный режим
sudo grep "Failed password" /var/log/auth.log
ls -ld ~/.ssh && ls -l ~/.ssh/authorized_keys   # 4. Права
```
**Пояснения:**
SSH-логи — в `journalctl -u ssh` и `/var/log/auth.log`. `-vvv` показывает ход аутентификации. Типовые проблемы: неверные права (`~/.ssh` — 700, ключи — 600), отсутствие ключа в `authorized_keys`, SELinux, неверный `sshd_config`.
