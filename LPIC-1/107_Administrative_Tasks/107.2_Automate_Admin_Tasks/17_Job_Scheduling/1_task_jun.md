**Практическая работа №1: Работа с cron (базовые задания)**

**Задание:**
1. Просмотрите текущие задания cron для вашего пользователя.
2. Добавьте задание, которое будет выполняться каждые 5 минут и записывать дату в файл.
3. Добавьте задание на ежедневный запуск в 2:30 ночи.
4. Добавьте задание на запуск каждую среду в 18:00.
5. Удалите одно из созданных заданий.
6. Проверьте логи cron на предмет выполнения заданий.

**Решение и пояснения:**
```bash
crontab -l                         # 1. Просмотр заданий текущего пользователя
crontab -e                         # Редактирование
# Добавить строки:
*/5 * * * * date >> ~/cron_test.log  # 2. Каждые 5 минут
30 2 * * * /path/to/backup.sh      # 3. Ежедневно в 2:30
0 18 * * 3 /path/to/cleanup.sh     # 4. Каждую среду (3) в 18:00
crontab -l                         # Просмотр после добавления
crontab -e                         # 5. Удалить нужную строку в редакторе
sudo grep CRON /var/log/syslog | tail -5  # 6. Проверка логов выполнения
```
**Пояснения:** Формат cron: `минута час день_месяца месяц день_недели команда`. `*` означает "любое значение". `*/5` в минутах — каждые 5 минут. День недели: 0-7 (0 и 7 = воскресенье). `crontab -e` открывает редактор для редактирования заданий пользователя.

**Практическая работа №2: Использование системного cron и директорий**

**Задание:**
1. Добавьте задание в системный cron через `/etc/crontab`.
2. Создайте задание в директории `/etc/cron.daily/`.
3. Настройте задание, которое выполняется при запуске системы.
4. Создайте задание, выполняющееся каждый час в 15 минут.
5. Проверьте синтаксис созданных заданий.
6. Убедитесь, что задания выполняются от нужного пользователя.

**Решение и пояснения:**
```bash
sudo nano /etc/crontab            # 1. Добавить: * * * * * root echo "test" >> /tmp/test.log
sudo nano /etc/cron.daily/backup  # 2. Скрипт, который будет выполняться ежедневно
# 3. В /etc/crontab: @reboot root /path/to/startup.sh
# 4. В /etc/crontab: 15 * * * * root /path/to/hourly.sh
sudo run-parts --test /etc/cron.daily  # 5. Тест скриптов в cron.daily
sudo grep "CMD" /var/log/syslog | grep cron  # 6. Проверка пользователя в логах
```
**Пояснения:** Системный cron (`/etc/crontab`) требует указания пользователя. Директории `cron.daily/`, `cron.hourly/` и т.д. выполняют скрипты периодически. `@reboot` — специальная директива для запуска при старте системы. `run-parts --test` проверяет, какие скрипты будут выполнены.

**Практическая работа №3: Работа с at (отложенный запуск)**

**Задание:**
1. Запланируйте выполнение команды через 2 минуты.
2. Запланируйте выполнение скрипта на конкретное время (например, 21:30).
3. Просмотрите очередь запланированных заданий at.
4. Удалите задание из очереди at.
5. Запланируйте задание на завтра в это же время.
6. Проверьте выполнение заданий в логах.

**Решение и пояснения:**
```bash
echo "echo 'Задание выполнено' > /tmp/at_test.txt" | at now + 2 minutes  # 1
at 21:30 -f /path/to/script.sh         # 2. Выполнение скрипта в 21:30
atq                                    # 3. Просмотр очереди
atrm <номер_задания>                   # 4. Удаление задания (номер из atq)
echo "/path/to/task.sh" | at tomorrow  # 5. На завтра в это же время
sudo grep "atd" /var/log/syslog | tail -5  # 6. Логи демона at
```
**Пояснения:** `at` выполняет команду один раз в указанное время. `now + 2 minutes` — через 2 минуты. `-f` указывает файл скрипта. `atq` показывает очередь, `atrm` удаляет. `at` удобен для разовых задач, в отличие от периодического cron.

**Практическая работа №4: Создание и мониторинг сложных заданий**

**Задание:**
1. Создайте cron-задание, которое проверяет доступность сайта каждые 10 минут.
2. Настройте перенаправление вывода (stdout и stderr) в разные файлы.
3. Добавьте условие: выполнять команду только если запущен определенный процесс.
4. Создайте задание, которое отправляет email с отчетом.
5. Настройте запуск задания только в рабочее время (9:00-18:00).
6. Реализуйте блокировку, чтобы задание не запускалось повторно, если предыдущий запуск еще не завершен.

**Решение и пояснения:**
```bash
crontab -e
# Добавить:
*/10 * * * * curl -I https://example.com >> ~/site_check.log 2>&1  # 1
0 * * * * ps aux | grep -q nginx && echo "Nginx работает" >> ~/status.log  # 3
0 8 * * 1-5 echo "Еженедельный отчет" | mail -s "Отчет" user@domain.com  # 4
*/30 9-18 * * 1-5 /path/to/work_task.sh  # 5. Только в рабочие часы
* * * * * flock -n /tmp/lockfile /path/to/long_task.sh  # 6. Блокировка
```
**Пояснения:** `2>&1` перенаправляет stderr в stdout. `&&` выполняет вторую команду только при успехе первой. `1-5` в дне недели означает с понедельника по пятницу. `9-18` в часах ограничивает выполнение. `flock -n` предотвращает параллельный запуск. Мониторинг через логи (`/var/log/syslog`).
