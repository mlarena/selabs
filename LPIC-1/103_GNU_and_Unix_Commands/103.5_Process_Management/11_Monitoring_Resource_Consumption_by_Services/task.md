**Практическая работа №1: Мониторинг ресурсов системных служб**      

**Задание:**      
1. Определите топ-5 системных служб по потреблению памяти.      
2. Найдите службы, использующие больше всего процессорного времени.      
3. Покажите статус всех активных служб systemd.      
4. Определите, какие службы запускаются автоматически при загрузке.      
5. Проверьте использование памяти конкретной службой (например, `sshd`).            
6. Создайте алиас для быстрой проверки ресурсов служб.            

**Решение и пояснения:**
```bash
ps aux --sort=-%mem | head -6 | grep -E "(systemd|^USER)"  # 1. Топ-5 по памяти
ps aux --sort=-%cpu | head -6 | grep -v "^USER"           # 2. Топ-5 по CPU
systemctl list-units --type=service --state=running       # 3. Активные службы
systemctl list-unit-files --type=service | grep enabled   # 4. Автозагрузка
systemctl status sshd | grep -A5 "Memory"                 # 5. Память sshd
alias svc-top='ps aux --sort=-%mem | head -11'            # 6. Алиас
```

**Пояснения:**       
`systemctl` управляет службами systemd.             
`--state=running` показывает только запущенные.       
`ps aux` сортировка по `%mem` или `%cpu` помогает найти "тяжелые" службы.       
Автозагрузка увеличивает потребление ресурсов при старте системы.

**Практическая работа №2: Детальный анализ ресурсов службы**

**Задание:**
1. Найдите PID основной службы (например, `nginx` или `apache2`).      
2. Определите общее потребление памяти службой и её дочерними процессами.      
3. Проверьте, сколько файловых дескрипторов использует служба.      
4. Определите, какие сетевые соединения открыты службой.      
5. Узнайте, сколько потоков использует служба.      
6. Проанализируйте использование ресурсов в реальном времени.      

**Решение и пояснения:**
```bash
systemctl show nginx --property=MainPID | cut -d= -f2     # 1. PID службы
ps -o pid,rss,cmd --ppid $(pidof nginx) | awk '{sum+=$2} END{print sum " KB"}'  # 2. Память
ls /proc/$(pidof nginx)/fd/ | wc -l                       # 3. Кол-во файловых дескрипторов
ss -tupn | grep $(pidof nginx)                            # 4. Сетевые соединения
ps -o nlwp $(pidof nginx) | tail -1                       # 5. Кол-во потоков (LWP)
top -p $(pidof nginx)                                     # 6. Реальный мониторинг
```
**Пояснения:**       
`/proc/[PID]/` содержит информацию о процессе.       
`fd/` — файловые дескрипторы.       
`pidof` возвращает PID процесса.       
`ss -tupn` показывает TCP/UDP соединения с PID.       
`nlwp` — количество легковесных процессов (потоков).       
`top -p` отслеживает конкретные PID.

**Практическая работа №3: Лимиты и ограничения служб**

**Задание:**      
1. Проверьте текущие лимиты ресурсов для службы (например, `nginx`).      
2. Определите максимальное количество файлов, которое может открыть служба.      
3. Проверьте, есть ли ограничения на память у службы.      
4. Узнайте, под каким пользователем запущена служба.      
5. Найдите конфигурационные файлы, где задаются лимиты.      
6. Измените лимиты для службы через systemd.      

**Решение и пояснения:**
```bash
cat /proc/$(pidof nginx)/limits                           # 1. Лимиты процесса
grep -i "nofile" /proc/$(pidof nginx)/limits              # 2. Макс. файлов
grep -i "memory" /proc/$(pidof nginx)/limits              # 3. Ограничения памяти
ps -o user,cmd -p $(pidof nginx) | grep -v USER           # 4. Пользователь службы
systemctl cat nginx | grep -i limit                       # 5. Лимиты в конфиге systemd
sudo systemctl edit nginx.service                         # 6. Редактирование лимитов
# Добавить: [Service] LimitNOFILE=65535
```
**Пояснения:**       
`/proc/[PID]/limits` показывает мягкие (soft) и жесткие (hard) лимиты.       
`nofile` — максимальное количество открытых файлов.       
`systemctl cat` показывает unit-файл службы.       
`systemctl edit` создает оверрайд для безопасного изменения настроек.

**Практическая работа №4: Автоматизированный мониторинг и алерты**      

**Задание:**      
1. Напишите скрипт для мониторинга ключевых служб.      
2. Проверяйте статус служб (активны/неактивны).      
3. Мониторьте потребление памяти критическими службами.      
4. Если служба использует >500MB памяти, выводите предупреждение.      
5. Если служба не запущена, пытайтесь её перезапустить.      
6. Настройте ежечасный запуск скрипта через cron.      

**Решение и пояснения:**
```bash
#!/bin/bash
# service_monitor.sh
SERVICES=("nginx" "ssh" "postgresql")

for service in "${SERVICES[@]}"; do
  if systemctl is-active --quiet $service; then
    echo "$service: активен"
    MEM=$(ps -o rss= -C $service | awk '{sum+=$1} END{print sum/1024 " MB"}')
    echo "  Память: $MEM"
    if [ ${MEM%.*} -gt 500 ]; then
      echo "  ВНИМАНИЕ: $service > 500MB!"
    fi
  else
    echo "$service: НЕ активен"
    systemctl restart $service 2>/dev/null && echo "  Перезапущен"
  fi
done
```
**Пояснения:**       
`systemctl is-active` проверяет статус службы.       
`ps -C` ищет процессы по имени.       
`${MEM%.*}` преобразует "123.45 MB" в 123 для сравнения.       
Cron: `0 * * * * /path/to/service_monitor.sh >> /var/log/service_monitor.log`.       
Логирование помогает отслеживать проблемы.
