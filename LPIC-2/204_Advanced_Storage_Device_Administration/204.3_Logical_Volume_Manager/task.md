**Практическая работа №1: Создание физических томов и группы томов**

**Задание:**
1. Создайте два loop-устройства.
2. Инициализируйте их как физические тома (PV).
3. Создайте группу томов (VG) из двух PV.
4. Посмотрите информацию о VG.
5. Объясните уровни абстракции LVM.

**Решение и пояснения:**
```bash
sudo pvcreate /dev/loop0 /dev/loop1          # 2. Физические тома
sudo pvs                                      # 2. Список PV
sudo vgcreate vgdata /dev/loop0 /dev/loop1   # 3. Группа томов
sudo vgs                                      # 4. Информация о VG
```
**Пояснения:**
LVM имеет три уровня: PV (физические тома), VG (группы томов, объединяющие PV), LV (логические тома, используемые как разделы). Гибкость: можно расширять тома и перемещать данные между дисками.

**Практическая работа №2: Создание и монтирование логического тома**

**Задание:**
1. Создайте логический том (LV) размером 100 МБ.
2. Отформатируйте его в ext4.
3. Смонтируйте LV.
4. Посмотрите дерево LVM.
5. Объясните путь `/dev/mapper`.

**Решение и пояснения:**
```bash
sudo lvcreate -L 100M -n lvdata vgdata       # 1. Логический том
sudo mkfs.ext4 /dev/vgdata/lvdata            # 2. Форматирование
sudo mkdir -p /mnt/lvm && sudo mount /dev/vgdata/lvdata /mnt/lvm   # 3
sudo lvs                                     # 4. Список LV
ls -l /dev/mapper/                           # 5. Симлинки
```
**Пояснения:**
`lvcreate` создаёт LV из свободного места VG. Устройство доступно как `/dev/vgdata/lvdata` и через `/dev/mapper/vgdata-lvdata`. После создания на нём размещают ФС и монтируют.

**Практическая работа №3: Расширение и уменьшение томов**

**Задание:**
1. Расширьте VG, добавив новый PV.
2. Расширьте LV и ФС.
3. Проверьте новый размер.
4. Уменьшите LV (осторожно).
5. Объясните порядок операций при расширении/сжатии.

**Решение и пояснения:**
```bash
sudo pvcreate /dev/loop2
sudo vgextend vgdata /dev/loop2              # 1. Расширение VG
sudo lvextend -L +50M -r /dev/vgdata/lvdata  # 2. Расширение LV и ФС (-r)
df -h /mnt/lvm                               # 3. Проверка
# Уменьшение (ext4): сначала umount и e2fsck
sudo umount /mnt/lvm
sudo e2fsck -f /dev/vgdata/lvdata
sudo lvreduce -L -20M -r /dev/vgdata/lvdata  # 4. Сжатие с ФС
```
**Пояснения:**
При расширении: расширить VG (при необходимости), затем LV с `-r` (авто-`resize2fs`). При сжатии: размонтировать, проверить ФС, уменьшить. Сжатие рискованно и требует проверки ФС; XFS уменьшать нельзя.

**Практическая работа №4: Снимки LVM**

**Задание:**
1. Создайте снимок LV.
2. Посмотрите список снимков.
3. Измените данные на оригинале.
4. Смонтируйте снимок и проверьте старое состояние.
5. Объясните назначение снимков для бэкапа.

**Решение и пояснения:**
```bash
sudo lvcreate -L 50M -s -n lvdata_snap /dev/vgdata/lvdata   # 1. Снимок
sudo lvs -a -o name,origin,lv_size                     # 2. Список
sudo mkdir -p /mnt/snap && sudo mount /dev/vgdata/lvdata_snap /mnt/snap
ls /mnt/snap                                           # 4. Старое состояние
```
**Пояснения:**
Снимок LVM фиксирует состояние тома на момент создания (CoW). Изменения на оригинале хранятся в отдельной области снимка. Снимки используют для согласованных бэкапов: монтируют снимок и копируют данные, не останавливая сервис.
