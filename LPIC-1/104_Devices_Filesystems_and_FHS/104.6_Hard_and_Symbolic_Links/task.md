**Практическая работа №1: Жёсткие ссылки**

**Задание:**
1. Создайте файл `original.txt` с текстом.
2. Создайте на него жёсткую ссылку `hardlink.txt`.
3. Посмотрите количество жёстких ссылок на файл.
4. Измените содержимое через ссылку и проверьте оригинал.
5. Удалите оригинал и проверьте доступность данных.

**Решение и пояснения:**
```bash
echo "hello" > original.txt
ln original.txt hardlink.txt        # 2. Жёсткая ссылка
ls -l original.txt hardlink.txt     # 3. Второй столбец - счётчик ссылок
echo "world" >> hardlink.txt        # 4. Изменение через ссылку
cat original.txt                    # 4. Оригинал изменился
rm original.txt                     # 5. Удаление имени
cat hardlink.txt                    # 5. Данные доступны
```
**Пояснения:**
Жёсткая ссылка — второе имя того же inode. У файла один набор данных и несколько имён. Изменения видны через любое имя. Удаление одного имени не удаляет данные, пока есть другие ссылки.

**Практическая работа №2: Символические ссылки**

**Задание:**
1. Создайте символическую ссылку `softlink.txt` на `hardlink.txt`.
2. Посмотрите, как отображается ссылка в `ls -l`.
3. Определите, куда указывает ссылка.
4. Удалите цель и проверьте ссылку.
5. Восстановите цель и проверьте ссылку снова.

**Решение и пояснения:**
```bash
ln -s hardlink.txt softlink.txt     # 1. Символическая ссылка
ls -l softlink.txt                  # 2. Стрелка -> на цель
readlink softlink.txt               # 3. Куда указывает
rm hardlink.txt                     # 4. Удаление цели
cat softlink.txt                    # 4. Ошибка: нет такого файла
echo "again" > hardlink.txt         # 5. Восстановление
cat softlink.txt                    # 5. Снова работает
```
**Пояснения:**
Символическая ссылка — отдельный файл, содержащий путь к цели (как ярлык). Если цель удалить, ссылка «повисает» (dangling). `ln -s` создаёт символическую, `ln` — жёсткую ссылку.

**Практическая работа №3: Различия и применение**

**Задание:**
1. Создайте жёсткую ссылку на файл и символьную на каталог.
2. Проверьте размер ссылок.
3. Определите inode оригинала и жёсткой ссылки.
4. Создайте символическую ссылку с абсолютным путём.
5. Объясните, почему на каталоги нельзя создавать жёсткие ссылки.

**Решение и пояснения:**
```bash
ln file.txt hard.txt                # 1. Жёсткая
ln -s /etc sym_etc                  # 1-2. Символическая на каталог
ls -li file.txt hard.txt            # 3. Одинаковый inode
ln -s /var/log/abs_link             # 4. Абсолютная ссылка
```
**Пояснения:**
Жёсткая ссылка делит inode с оригиналом (одинаковый номер inode, тот же размер). Символическая — отдельный inode и путь. Жёсткие ссылки на каталоги запрещены, чтобы не создавать циклы в файловой системе.

**Практическая работа №4: Ссылки в администрировании**

**Задание:**
1. Найдите все символические ссылки в `/etc`.
2. Найдите битые (повисшие) символические ссылки.
3. Найдите файлы с более чем одной жёсткой ссылкой.
4. Создайте «переключатель» версии через символическую ссылку.
5. Объясните, как ссылки помогают администрированию.

**Решение и пояснения:**
```bash
find /etc -type l                          # 1. Символические ссылки
find / -xtype l 2>/dev/null                # 2. Битые ссылки
find /etc -type f -links +1 2>/dev/null    # 3. Файлы с >1 жёсткой ссылкой
ln -sf /opt/app-1.2 current                # 4. Переключение версии
```
**Пояснения:**
`find -type l` ищет символические ссылки, `-xtype l` — битые. `-links +1` находит файлы с несколькими жёсткими ссылками. Символическая ссылка `current` позволяет переключать активную версию приложения, не меняя конфигурацию сервисов.
