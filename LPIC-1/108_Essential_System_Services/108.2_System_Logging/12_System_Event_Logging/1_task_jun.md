**Практическая работа №1: Работа с журналом systemd (journalctl)**

**Задание:**       
1. Покажите последние 20 строк системного журнала.       
2. Отфильтруйте логи по службе `ssh`.     
3. Покажите логи с сегодняшней даты.     
4. Найдите сообщения об ошибках (error) в логах.     
5. Отслеживайте логи в реальном времени.     
6. Сохраните логи конкретной службы в файл.     

**Решение и пояснения:**
```bash
sudo journalctl -n 20                  # 1. Последние 20 строк
sudo journalctl -u ssh                 # 2. Логи службы ssh
sudo journalctl --since today          # 3. Логи с сегодня
sudo journalctl -p err                 # 4. Сообщения уровня ERROR
sudo journalctl -f                     # 5. Режим слежения (Ctrl+C для выхода)
sudo journalctl -u nginx > nginx.log   # 6. Сохранение в файл
```
**Пояснения:**      
`journalctl` — основная утилита для просмотра логов systemd.      
`-n N` показывает N последних строк.      
`-u` фильтрует по службе.      
`-p` задает приоритет (err, warning, info).           
`-f` показывает новые записи по мере появления.

**Практическая работа №2: Анализ традиционных логов (/var/log)**

**Задание:**     
1. Изучите структуру каталога `/var/log`.     
2. Просмотрите системные логи (`syslog` или `messages`).     
3. Проверьте логи аутентификации (`auth.log`).     
4. Найдите неудачные попытки входа в систему.     
5. Покажите логи ядра (`kern.log`).     
6. Отслеживайте логи apache/nginx (если установлены).     

**Решение и пояснения:**
```bash
ls -la /var/log/                       # 1. Содержимое каталога
sudo tail -20 /var/log/syslog          # 2. Системные логи
sudo tail -20 /var/log/auth.log        # 3. Логи аутентификации
sudo grep "Failed password" /var/log/auth.log  # 4. Неудачные входы
sudo tail -20 /var/log/kern.log        # 5. Логи ядра
sudo tail -20 /var/log/nginx/access.log 2>/dev/null || echo "Nginx не установлен"  # 6
```
**Пояснения:**      
Традиционные логи хранятся в `/var/log`.      
`auth.log` содержит информацию о входах, sudo и т.д.      
`kern.log` — сообщения ядра.      
`2>/dev/null` подавляет ошибку если файл не существует.      
Утилита `tail` показывает конец файла.

**Практическая работа №3: Поиск и фильтрация в логах**     

**Задание:**     
1. Найдите все логи за последний час.     
2. Поищите упоминания IP-адреса в логах.     
3. Отфильтруйте логи по конкретному пользователю.     
4. Покажите логи с временными метками в определенном диапазоне.     
5. Найдите наиболее частые сообщения в логах.     
6. Создайте отчет о критических ошибках за день.     

**Решение и пояснения:**
```bash
sudo journalctl --since "1 hour ago"   # 1. За последний час
sudo journalctl | grep "192.168.1.1"   # 2. Поиск по IP
sudo journalctl _UID=$(id -u username) # 3. По пользователю
sudo journalctl --since "09:00" --until "10:00"  # 4. Диапазон времени
sudo journalctl -p err --since today | cut -d' ' -f5- | sort | uniq -c | sort -nr  # 5. Частые ошибки
sudo journalctl -p crit --since today > critical_errors.txt  # 6. Отчет
```
**Пояснения:**      
`--since` и `--until` задают временной диапазон.      
`_UID=` фильтрует по ID пользователя.      
`cut -d' ' -f5-` удаляет первые 4 поля (дата, время и т.д.).           
`uniq -c` подсчитывает повторения.      
`-p crit` показывает критические сообщения.

**Практическая работа №4: Ротация и управление логами**

**Задание:**     
1. Проверьте конфигурацию ротации логов.     
2. Вручную запустите ротацию логов.     
3. Просмотрите заархивированные логи.     
4. Определите, сколько места занимают логи.     
5. Очистите старые логи (старше 30 дней).     
6. Настройте мониторинг размера логов.     

**Решение и пояснения:**
```bash
cat /etc/logrotate.conf                # 1. Основной конфиг
ls /etc/logrotate.d/                   # 1. Конфиги сервисов
sudo logrotate -f /etc/logrotate.conf  # 2. Принудительная ротация
zcat /var/log/syslog.1.gz 2>/dev/null  # 3. Просмотр сжатого лога
sudo du -sh /var/log                   # 4. Размер логов
sudo find /var/log -type f -name "*.log" -mtime +30 -delete  # 5. Удаление старых
# 6. Скрипт мониторинга:
du -sh /var/log | awk '{print "Логи занимают: "$1}'
```
**Пояснения:**      
`logrotate` автоматически архивирует и удаляет старые логи.                 
`-f` принудительный запуск.           
`zcat` читает сжатые gzip файлы.           
`-mtime +30` — файлы старше 30 дней.           
Удаление логов требует осторожности — некоторые логи важны для аудита.
