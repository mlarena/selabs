**Практическая работа №1: Базовое управление процессами**

**Задание:**     
1. Запустите процесс `sleep 300` в фоновом режиме.     
2. Найдите его PID (идентификатор процесса).     
3. Приостановите (остановите) этот процесс.     
4. Возобновите выполнение остановленного процесса.     
5. Завершите процесс разными способами.     
6. Проверьте, что процесс завершен.     

**Решение и пояснения:**
```bash
sleep 300 &                    # 1. Запуск в фоне (& возвращает PID)
jobs -l                        # 2. Показать фоновые процессы (PID в квадратных скобках)
# или: ps aux | grep sleep     # 2. Альтернативный поиск
kill -STOP %1                  # 3. Приостановка по номеру задачи (или kill -STOP <PID>)
kill -CONT %1                  # 4. Продолжение выполнения
kill %1                        # 5. Завершение сигналом TERM (мягкое)
kill -KILL %1                  # 5. Сигнал KILL (принудительное)
# или: kill -9 <PID>           # 5. Альтернативная запись
ps aux | grep sleep            # 6. Проверка, что процесса нет
```
**Пояснения:**          
`&` запускает команду в фоне.      
`jobs -l` показывает фоновые задачи текущей сессии.        
`%1` ссылается на задачу №1.         
Сигналы:         
`STOP` — приостановка, `        
CONT` — продолжение,         
`TERM` (по умолчанию) — мягкое завершение,         
`KILL` (9) — принудительное завершение.

**Практическая работа №2: Мониторинг и анализ процессов**

**Задание:**      
1. Запустите 3 фоновых процесса: `sleep 200`, `sleep 300`, `sleep 400`.     
2. Выведите список всех процессов в древовидной форме.     
3. Найдите родительский процесс (PPID) для текущего shell.     
4. Определите, какие процессы используют больше всего CPU.     
5. Отслеживайте процессы в реальном времени.     
6. Определите полный путь к исполняемому файлу процесса.     

**Решение и пояснения:**
```bash
sleep 200 & sleep 300 & sleep 400 &  # 1. Запуск 3 процессов
pstree -p                           # 2. Древовидное представление с PID
echo $$                             # 3. PID текущего shell
ps -ef | grep $$ | awk '{print $3}' # 3. PPID текущего shell (родитель)
top -o %CPU                         # 4. Сортировка по CPU (q для выхода)
# или: ps aux --sort=-%cpu | head -10  # 4. Статичный список
ps -p <PID> -o cmd                  # 6. Команда процесса (замените <PID>)
ls -l /proc/<PID>/exe              # 6. Ссылка на исполняемый файл
```
**Пояснения:** 
`pstree` показывает иерархию процессов.           
`$$` — PID текущего shell.      
`ps -ef` показывает все процессы с родителями.      
`top -o %CPU` сортирует по загрузке CPU.      
`/proc/<PID>/exe` — символическая ссылка на исполняемый файл процесса.

**Практическая работа №3: Приоритеты процессов и nice**

**Задание:**      
1. Запустите процесс `sleep 500` с низким приоритетом (nice = 10).     
2. Запустите процесс `sleep 600` с высоким приоритетом (nice = -5, нужны права).     
3. Проверьте значение nice для запущенных процессов.     
4. Измените приоритет уже запущенного процесса.     
5. Запустите команду с максимальным приоритетом (только для root).     
6. Определите процессы с высоким приоритетом в системе.     

**Решение и пояснения:**
```bash
nice -n 10 sleep 500 &            # 1. Запуск с низким приоритетом (nice=10)
sudo nice -n -5 sleep 600 &       # 2. Высокий приоритет (нужен sudo)
ps -l -p $(pgrep sleep)           # 3. Проверка NI (nice) значения
renice 15 -p <PID>                # 4. Изменение приоритета запущенного процесса
sudo renice -20 -p <PID>          # 5. Максимальный приоритет (-20)
ps -eo pid,ni,cmd | sort -k2 -n | head -10  # 6. Процессы с высоким приоритетом
```
**Пояснения:**      
`nice` — от -20 (высший) до 19 (низший). Обычные пользователи могут только понижать приоритет.      
`renice` меняет приоритет запущенного процесса.      
`ps -l` показывает колонку NI (nice).      
`pgrep` ищет PID по имени процесса.

**Практическая работа №4: Управление группами процессов**

**Задание:**     
1. Запустите группу процессов: `sleep 700 & sleep 800 &`.     
2. Определите PGID (идентификатор группы процессов).     
3. Завершите всю группу процессов одним сигналом.     
4. Запустите процесс в новой сессии (отдельно от текущего shell).     
5. Определите процессы, принадлежащие определенной группе.     
6. Отправьте сигнал всем процессам в группе.     

**Решение и пояснения:**
```bash
sleep 700 & sleep 800 &           # 1. Запуск группы процессов
ps -o pid,pgid,cmd | grep sleep   # 2. Показывает PID и PGID
kill -TERM -<PGID>                # 3. Завершение группы по PGID (минус перед PGID)
setsid sleep 900                  # 4. Запуск в новой сессии (в фоне: setsid sleep 900 &)
ps -o pid,pgid,cmd -g <PGID>      # 5. Процессы определенной группы
pkill -<SIGNAL> -g <PGID>         # 6. Отправка сигнала группе (например: pkill -TERM -g 1234)
```
**Пояснения:**            
Группа процессов (PGID) позволяет управлять несколькими процессами вместе.        
`-` перед PGID в `kill` означает "вся группа".         
`setsid` запускает процесс в новой сессии.         
`pkill` работает с группами через `-g`.           
Управление группами полезно для завершения связанных процессов.
